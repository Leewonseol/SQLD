# [ID-05] 외래키와 참조무결성

> [!IMPORTANT]
> **핵심 법리:**
> 외래키(FK)는 다른 테이블(부모 테이블)의 기본키를 참조하는 컬럼으로, 참조무결성(Referential Integrity) 규칙상 그 값은 반드시 부모 테이블에 실제로 존재하는 값이거나 NULL이어야 한다. 부모 테이블에 없는 값을 자식 테이블의 외래키에 저장하는 것은 허용되지 않는다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지가 "외래키는 부모 테이블에 존재하는 값만 가질 수 있다"고 서술하는지, 아니면 "부모 테이블에 없는 값도 사용할 수 있다"고 서술하는지 확인한다. 외래키 컬럼 자체가 NULL을 허용하는지 여부는 참조무결성과 별개로, 그 관계가 필수(NOT NULL)로 설정되었는지에 달려 있다.
>
> [!WARNING]
> **반복 오답:**
> "부모 테이블에 없는 값도 외래키로 사용할 수 있다"며 참조무결성 규칙을 정반대로 서술하는 함정, 외래키 컬럼은 항상 NULL이 될 수 없다고 과장하는 함정(실제로는 관계가 선택적이면 NULL 허용 가능).

## 1. 판시사항

- 외래키가 지켜야 할 참조무결성 규칙은 무엇인가?
- 외래키 컬럼은 NULL 값을 가질 수 있는가?
- 부모 테이블에 존재하지 않는 값을 자식 테이블의 외래키에 저장할 수 있는가?

## 2. 핵심 법리

> 외래키는 자식 테이블에서 부모 테이블의 기본키(또는 유일키)를 참조하기 위해 두는 컬럼으로, 참조무결성 규칙에 따라 그 값은 반드시 부모 테이블에 실제로 존재하는 값이거나 NULL 중 하나여야 한다. 부모 테이블에 존재하지 않는 값을 자식 테이블의 외래키에 저장하면 참조무결성이 깨지며, 일반적으로 DBMS는 이런 저장을 제약조건 위반으로 거부한다. 다만 외래키 컬럼이 NULL을 가질 수 있는지 여부는 참조무결성과는 별개의 문제로, 그 관계가 선택적 관계(옵션)로 설계되었다면 외래키 컬럼은 NULL을 허용할 수 있다.

## 3. 법리 적용 분기

```text
선지가 외래키에 대해 서술하는 내용은?
│
├─ "부모 테이블에 존재하는 값(또는 NULL)만 가질 수 있다"
│  └─ 참조무결성 규칙 그대로 — 옳은 서술
│
├─ "부모 테이블에 없는 값도 사용할 수 있다"
│  └─ 참조무결성 규칙을 반대로 서술 — 틀린 서술
│
└─ "외래키 컬럼은 NULL을 가질 수 있다" (관계가 선택적인 경우)
   └─ 참조무결성과 별개의 문제 — 옳은 서술
```

## 4. 이 문제들이 유사한 이유

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 외래키 값이 부모 테이블에 존재하는 값(또는 NULL)이어야 한다는 참조무결성 규칙을 판별하는 동일한 규칙 |
| 공통 결정 사실 | 선지가 "부모에 존재하는 값만"이라고 서술하는지 "부모에 없는 값도 가능"이라고 서술하는지 |
| 반복되는 오답 구조 | 참조무결성 규칙을 정반대로 서술(D2), 외래키 컬럼의 NULL 허용 여부를 참조무결성과 혼동 |
| 정답이 달라지는 조건 | 참조무결성 규칙 자체를 반대로 서술했는지, 아니면 NULL 허용이라는 별개 규칙을 정확히 서술했는지 |

### 사실관계

"외래키(Foreign Key)에 대한 설명으로 옳지 않은 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나(④)는 "부모 테이블에 없는 키 값도 외래키에서 사용할 수 있다"는 취지로 서술되고, 다른 하나(②)는 "외래키 컬럼은 NULL 값을 가질 수 있다"는 취지로 서술된다.

### 쟁점

외래키가 참조무결성 규칙에 따라 반드시 부모 테이블에 존재하는 값만 가져야 하는지, 아니면 임의의 값을 가질 수 있는지가 쟁점이다.

### 적용 법리

참조무결성 규칙상 외래키 값은 반드시 부모 테이블(참조되는 테이블)의 기본키 값 중 하나이거나 NULL이어야 한다. 부모 테이블에 존재하지 않는 값을 자식 테이블의 외래키에 저장하는 것은 참조무결성 위반이다. 반면 외래키 컬럼 자체가 NULL을 가질 수 있는지는 별개 문제로, 그 관계가 필수관계로 설정되지 않은 이상 NULL을 허용할 수 있다.
