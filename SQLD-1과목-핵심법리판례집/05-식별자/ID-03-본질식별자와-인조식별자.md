# [ID-03] 본질식별자와 인조식별자

> [!IMPORTANT]
> **핵심 법리:**
> 본질식별자는 업무 분석을 통해 자연적으로 발생한 값을 그대로 식별자로 사용하는 것이고, 인조식별자는 업무상 자연발생 식별자가 마땅치 않거나 복잡할 때 인위적으로 일련번호 등을 부여해 만든 식별자다. 이 둘의 구분 기준은 "식별자 값이 업무에서 자연적으로 생겨났는가, 인위적으로 만들어졌는가"이다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지가 "의미를 내포한다/복합키가 되기 쉽다"고 서술하면 본질식별자, "의미가 없는 일련번호/자동증가/관리가 간편하다"고 서술하면 인조식별자다. 다만 인조식별자를 쓰면 원래의 자연 식별자에서 중복이 발생해도 DB가 이를 자동으로 걸러주지는 않는다는 점에 주의해야 한다.
>
> [!WARNING]
> **반복 오답:**
> 본질식별자의 "복합키가 되기 쉽다"는 특징을 "그래서 관리가 간편하다"는 인조식별자의 장점과 뒤섞는 함정, 인조식별자를 쓰면 데이터 중복 여부를 DB가 자동으로 감지·차단해준다고 과장하는 함정, 인조식별자가 사용자에게 의미 파악이 쉽다고 반대로 서술하는 함정, 본질식별자가 검색 성능이 항상 우수하다고 과장하는 함정(D4).

## 1. 판시사항

- 본질식별자와 인조식별자는 각각 어떤 기준으로 식별자 값을 얻는가?
- 본질식별자·인조식별자를 각각 사용할 때 얻는 장점과 발생할 수 있는 문제점은 무엇인가?
- 인조식별자를 사용하면 원래 자연 식별자의 중복 문제를 DB가 자동으로 해결해주는가?

## 2. 핵심 법리

> **본질식별자**는 업무 분석 과정에서 자연적으로 만들어진 값(예: 주민등록번호, 학번)을 그대로 주식별자로 사용하는 것으로, 식별자 자체가 데이터의 의미를 내포하고 여러 속성이 결합된 복합키 형태가 되기 쉽다. **인조식별자**는 본질식별자가 지나치게 복잡하거나 자연 식별자를 찾기 어려울 때, 업무와 무관한 일련번호(주로 자동증가값)를 인위적으로 부여해 사용하는 식별자로, 단일 속성으로 구성되어 관리가 간편하지만 값 자체에는 의미가 없어 사용자가 의미를 파악하기 어렵다. 인조식별자를 도입해도 원래의 자연 식별자(본질식별자 후보)에 대한 중복 통제는 DB가 자동으로 해주지 않으므로, 별도의 유일성 제약이나 검증 로직이 없으면 데이터 중복 입력이 발생할 수 있다.

## 3. 법리 적용 분기

```text
식별자 값의 출처는?
│
├─ 업무 분석을 통해 자연적으로 발생한 값을 그대로 사용
│  └─ 본질식별자 — 의미 내포, 복합키가 되기 쉬움, 별도 중복차단 없으면 중복 위험은 그대로
│
└─ 업무와 무관하게 인위적으로 일련번호(자동증가 등)를 부여
   └─ 인조식별자 — 의미 없음, 단일키로 관리 간편, 그러나 원래 자연 식별자의 중복은 자동 차단되지 않음
```

### 사실관계

"본질식별자에 대한 설명으로 옳지 않은 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나(③)는 본질식별자가 복합키로 구성되는 경우가 많아 관리가 간편하다는 취지로 서술된다.

### 쟁점

"관리가 간편하다"는 장점이 본질식별자가 아니라 인조식별자의 특징인지가 쟁점이다.

### 적용 법리

본질식별자는 업무 분석을 통해 자연적으로 발생한 값을 그대로 사용하므로 여러 속성이 결합된 복합키 형태가 되기 쉽고, 오히려 관리가 복잡해질 수 있다. 관리 간편성은 단일 속성의 일련번호로 구성되는 인조식별자의 장점이다. 따라서 "복합키로 구성되어 관리가 간편하다"는 서술은 두 개념의 특징을 뒤바꾼 것이다.

### 주문

**정답: ③**

→ 적용되는 핵심 법리: 관리 간편성은 단일 속성으로 구성되는 인조식별자의 장점이지, 여러 속성이 결합되기 쉬운 본질식별자의 장점이 아니다

## 9. 출제자가 바꾸는 사실

- 본질식별자와 인조식별자의 장점(의미 내포 vs 관리 간편)을 서로 바꿔치기
- 인조식별자가 자연 식별자의 중복을 DB가 자동으로 감지·차단한다고 과장
- 인조식별자가 사용자에게 의미 파악이 쉽다고 반대로 서술
- 본질식별자의 검색 성능이 "항상" 우수하다고 과장

## 10. 시험용 한 줄 법리
