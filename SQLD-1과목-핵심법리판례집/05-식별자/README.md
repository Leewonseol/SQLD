# 05 식별자

기본 학습은 아래 비교표와 결정 트리로 진행한다. 상세 근거와 기출 해설이 필요할 때만 하단 "상세 법리 파일" 링크를 연다. 관계 자체의 참여도·카디널리티는 [04-관계와-ERD/README.md](../04-관계와-ERD/README.md)를 참고한다.

## 1. 핵심 개념 비교표

### 주식별자 4요건

| 요건 | 의미 | 반복 함정 |
| --- | --- | --- |
| 유일성 | 모든 인스턴스를 서로 구분 | 중복을 허용해도 된다고 서술 |
| 최소성 | 유일성을 만족하는 최소 속성 수 | 최대한 많은 속성을 조합하라고 서술(범위 과장) |
| 불변성 | 값이 자주 바뀌지 않음 | 변경 가능한 값(주소 등)을 식별자로 사용 |
| 존재성 | NULL을 허용하지 않음(개체무결성) | NULL 허용을 개체무결성 위반으로 인식 못함 |

### 식별자 분류(3개 독립 축)

| 분류축 | 구분 | 판단 기준 |
| --- | --- | --- |
| 대표성 | 주식별자 / 보조식별자 | 관계·참조에 대표로 쓰이는가 |
| 생성 방식 | 본질식별자 / 인조식별자 | 업무에서 자연 발생했는가, 인위적으로 만들었는가 |
| 속성 수 | 단일식별자 / 복합식별자 | 속성이 몇 개 결합되었는가 |
| 자체 생성 여부 | 내부식별자 / 외부식별자 | 엔터티 스스로 만들었는가, 관계로 받아들였는가 |

### 본질식별자 vs 인조식별자

| 구분 | 본질식별자 | 인조식별자 |
| --- | --- | --- |
| 생성 | 업무에서 자연 발생 | 설계상 새로 생성(자동증가 등) |
| 목적 | 업무 의미 반영 | 단순화·성능·관리 편의 |
| 장점 | 의미를 내포, 검색 시 의미 파악 쉬움 | 단일키가 되기 쉬워 관리 간편 |
| 주의 | 복합키가 되기 쉬움 | 자연식별자의 중복을 DB가 자동으로 막아주지 않음 |

### 식별관계 vs 비식별관계

| 구분 | 식별관계 | 비식별관계 |
| --- | --- | --- |
| 부모 키 전달 | 자식의 주식별자(PK)에 포함 | 자식의 일반 외래키(FK)로만 존재 |
| 자식 독립성 | 낮음(부모 없이 생성 불가) | 상대적으로 높음(FK가 NULL이면 생성 가능) |
| 핵심 판정 | 부모 식별자가 PK 구성에 포함되는가 | 부모 식별자가 FK로만 존재하는가 |
| ERD 표기 | 실선 | 점선 |

### 외래키·참조무결성

| FK 값 | 판정 |
| --- | --- |
| 부모 테이블에 실제로 존재하는 값 | 참조무결성 충족 |
| NULL(관계가 선택참여인 경우) | 참조무결성 충족(예외적으로 허용) |
| 부모 테이블에 없는 값 | 참조무결성 위반 |

## 2. 판정용 결정 트리

```text
① 주식별자 성립 확인
유일한가? → 최소 속성만인가? → 안 바뀌는가? → NULL 없는가?
→ 넷 다 예 → 주식별자 후보
```

```text
② 식별관계·비식별관계 확인
부모의 식별자가 자식에게 전달됐는가?
├─ 자식의 주식별자에 포함 → 식별관계(실선)
└─ 자식의 일반 외래키로만 존재 → 비식별관계(점선)
```

```text
ERD형: 부모·자식 확인 → 최소 참여 확인 → 최대 카디널리티 확인 → 식별·비식별 확인 → 선지별 O/X 판정
```

식별자 문제는 "어느 분류축을 묻는가"(대표성/생성방식/속성수/자체생성 여부)를 먼저 확정한 뒤 판정한다 — 네 축은 서로 독립적으로 동시에 적용된다.

## 3. 유사 사례 비교

| 사례 | 결정적 사실 | 적용 개념 | 결론 |
| --- | --- | --- | --- |
| 회원명(동명이인 가능) | 유일성 미충족 | 주식별자 요건 | 주식별자 부적합 |
| 최대한 많은 속성을 묶은 식별자 | 최소성 위반 | 주식별자 요건 | 부적합(불필요한 속성 포함) |
| 연락처ID(자동증가) | 인위적으로 생성 | 본질/인조식별자 | 인조식별자 |
| 연락처번호(중복 가능) | 유일하지 않음 | 본질식별자 요건 | 본질식별자 아님 |
| 주문-주문상품(주문번호가 주식별자 일부) | 부모 식별자가 PK 구성에 포함 | 식별/비식별관계 | 식별관계 |
| 회원-주문(회원번호가 FK로만 존재) | 부모 식별자가 일반속성 | 식별/비식별관계 | 비식별관계 |

## 4. 반복 오답

| 선지 표현 | O/X | 틀린 이유 | 올바르게 고치면 |
| --- | :-: | --- | --- |
| 주식별자는 최대한 많은 속성을 조합해 구성한다 | X | 최소성 원칙 위반(범위 과장, D4) | 주식별자는 유일성을 만족하는 최소 속성으로 구성한다 |
| 주식별자와 보조식별자는 한 엔터티에 동시에 존재할 수 없다 | X | 동시에 존재 가능(조건 누락, D3) | 한 엔터티에 주식별자와 보조식별자가 모두 존재할 수 있다 |
| 인조식별자를 쓰면 자연식별자의 중복을 DB가 자동으로 차단한다 | X | 별도의 중복 체크 로직이 필요(범위 과장, D4) | 인조식별자를 써도 자연식별자의 중복은 자동으로 차단되지 않는다 |
| 본질식별자는 검색 성능이 항상 인조식별자보다 우수하다 | X | "항상"은 과장(범위 과장, D4) | 본질식별자는 복합키가 되기 쉬워 오히려 성능이 저하될 수 있다 |
| 외부식별자가 포함되면 무조건 식별관계다 | X | 주식별자 포함 여부가 핵심, 단순 포함 여부 아님(조건 누락, D3) | 외부식별자가 자식의 주식별자에 포함되면 식별관계, 일반속성으로만 쓰이면 비식별관계다 |
| 외래키는 부모 테이블에 없는 값도 가질 수 있다 | X | 참조무결성 위반(반대 개념 적용, D2) | 외래키는 부모 테이블에 존재하는 값이거나 NULL만 가질 수 있다 |

## 5. 자가 점검

표와 결정 트리를 가린 상태에서 답한다.

1. (핵심개념설명형) 주식별자가 성립하기 위한 유일성·최소성·불변성·존재성 네 요건을 각각 한 문장으로 설명하시오.
2. (핵심개념설명형) 참조무결성이란 무엇이며, 외래키 값이 만족해야 할 조건을 한 문장으로 쓰시오.
3. (유사개념구별형) 본질식별자와 인조식별자를 가르는 핵심 기준 한 문장을 쓰고, 각각의 대표적 장점을 하나씩 대응시키시오.
4. (유사개념구별형) 식별관계와 비식별관계를 가르는 핵심 기준 한 문장을 쓰시오.
5. (사례판정형) [주문] 엔터티와 [주문상품] 엔터티가 있고, 주문상품의 주식별자가 "주문번호+상품코드"로 구성된다. 이 관계는 식별관계인가 비식별관계인가? 판정 기준과 함께 답하시오.
6. (사례판정형) 설계자가 "회원명"을 주식별자 후보로 제안했다. 어떤 요건 위반인지와 그 이유를 쓰시오.
7. (반복오답교정형) "인조식별자를 사용하면 자연식별자의 중복을 DB가 자동으로 차단해 준다"는 서술의 오류를 지적하고 올바른 문장으로 고치시오.
8. (결정트리재현형) 아래 빈칸을 채우시오.

```text
후보 속성이 인스턴스를 구별할 수 있는가?
│
├─ 아니오 → 식별자 아님
│
└─ 예
   ├─ 유일한가?(유일성)
   │  ├─ 아니오 → (        )
   │  └─ 예
   │     ├─ 최소 속성만으로 구성됐는가?(최소성)
   │     │  ├─ 아니오 → (        )
   │     │  └─ 예
   │     │     ├─ 값이 자주 변경되지 않는가?(불변성)
   │     │     │  ├─ 아니오 → (        )
   │     │     │  └─ 예
   │     │     │     ├─ NULL이 허용되지 않는가?(존재성)
   │     │     │     │  ├─ 예 → (        )
   │     │     │     │  └─ 아니오 → (        )
```

<details>
<summary>자가 점검 정답</summary>

1. 유일성=모든 인스턴스를 서로 구분할 수 있어야 함, 최소성=유일성을 만족하는 최소 속성 수로 구성, 불변성=값이 자주 바뀌지 않아야 함, 존재성=NULL을 허용하지 않음(개체무결성).
2. 참조무결성은 외래키 값이 부모 테이블에 실제로 존재하는 값이거나 NULL이어야 한다는 규칙이다(부모에 없는 값은 허용되지 않음).
3. 기준: 식별자 값이 업무에서 자연발생했는가(본질식별자), 인위적으로 생성했는가(인조식별자). 본질식별자는 의미를 내포한다는 장점, 인조식별자는 단일키로 관리가 간편하다는 장점이 있다.
4. 부모의 식별자가 자식의 주식별자에 포함되면 식별관계, 자식의 일반 외래키로만 존재하면 비식별관계다.
5. 식별관계다 — 부모(주문)의 식별자인 주문번호가 자식(주문상품)의 주식별자 구성에 포함되어, 부모 없이는 주문상품 인스턴스가 독립적으로 생성될 수 없기 때문이다.
6. 유일성 위반이다 — 회원명은 동명이인이 존재할 수 있어 인스턴스를 서로 구분하지 못하므로 주식별자 후보가 될 수 없다.
7. 오류: 인조식별자는 그 자체로 단순 일련번호일 뿐이므로, 원래의 자연식별자(본질식별자 후보)에 중복이 있어도 DB가 자동으로 걸러주지 않는다. 올바른 문장: "인조식별자를 사용해도 자연식별자의 중복은 자동으로 차단되지 않으며 별도의 유일성 제약이 필요하다."
8. 위에서부터 순서대로: 유일성 위반(탈락) / 최소성 위반 / 불변성 위반 / 주식별자 후보 / 존재성 위반.

</details>

| 내부식별자의 예시로 가장 적절한 것 고르기 | ③ | 회원 엔터티의 회원ID는 회원 스스로 생성한 식별자이므로 내부식별자 |
| 외래키 설명 중 옳지 않은 것 고르기 | ④ | "부모 테이블에 없는 값도 사용 가능"은 참조무결성 규칙을 반대로 서술 |

</details>

### 선지 O/X 훈련

**문제: 주식별자의 특징으로 옳지 않은 것은? (이기적 단원별(식별자) page_10 문제02, ID-01)**

| 선지 핵심 주장 | 내 판정 | 정답 | 결정적 이유 |
| --- | :-: | :-: | --- |
| ① 유일성: 주식별자 값으로 모든 인스턴스를 서로 구분할 수 있어야 한다 | | O | 유일성의 정의 그대로 |
| ② 최소성: 유일성을 만족하는 최소한의 속성 개수로 구성해야 한다 | | O | 최소성의 정의 그대로 |
| ③ 불변성: 주식별자 값은 자주 변경될 수 있다 | | X | 불변성은 "자주 바뀌지 않아야 함"인데 방향을 반대로 서술 |
| ④ 존재성: 주식별자가 지정되면 반드시 데이터 값이 존재해야 한다(NULL 불허) | | O | 존재성(개체무결성)의 정의 그대로 |
