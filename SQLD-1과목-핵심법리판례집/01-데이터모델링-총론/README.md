# 01 데이터 모델링 총론

기본 학습은 아래 비교표와 결정 트리로 진행한다. 상세 근거와 기출 해설이 필요할 때만 하단 "상세 기출 해설" 링크를 연다.

## 1. 핵심 개념 비교표

### 모델링 유의사항

| 구분 | 중복 | 비유연성 | 비일관성 |
| --- | --- | --- | --- |
| 핵심 상황 | 같은 데이터가 여러 곳에 반복 저장 | 애플리케이션 변경에 데이터 모델이 종속됨 | 연관관계가 불명확해 일부 데이터만 변경 |
| 결정적 단서 | 여러 위치에 동일 데이터 | 연계성이 높음 | 정합성 불일치 |
| 반복 함정 | 중복을 비일관성으로 설명 | 연계성을 장점으로 설명 | 일부만 변경된 것을 중복으로 설명 |

### 개념·논리·물리 모델

| 구분 | 개념 모델 | 논리 모델 | 물리 모델 |
| --- | --- | --- | --- |
| 관심 대상 | 핵심 업무 개념과 관계 | 속성·식별자·관계·정규화 | 테이블·컬럼·자료형·인덱스 |
| DBMS 종속성 | 낮음 | 원칙적으로 낮음(독립적) | 높음 |
| 대표 산출물 | 개념 ERD | 논리 ERD | 물리 스키마 |
| 반복 함정 | 물리적 특성(인덱스 등) 섞기 | 반정규화를 이 단계 작업으로 서술 | — |

### 3단계 스키마

| 구분 | 외부 스키마 | 개념 스키마 | 내부 스키마 |
| --- | --- | --- | --- |
| 관점 | 사용자·응용프로그램별 개별 뷰 | 조직 전체 통합 논리 구조 | 물리적 저장 구조 |
| 핵심 질문 | 누가 무엇을 보는가 | 전체 구조는 무엇인가 | 어떻게 저장되는가 |
| 반복 함정 | — | "논리 스키마"를 3단계에 끼워넣기 | 물리적 모델링과 완전히 동일시 |

### 모델링 세 가지 관점

| 구분 | 데이터 관점 | 프로세스 관점 | 상관 관점 |
| --- | --- | --- | --- |
| 판단 질문 | 무엇을 저장하는가 | 어떻게 처리하는가 | 업무 흐름에 따라 데이터가 어떻게 조작되는가 |
| 반복 함정 | — | 상관 관점 정의와 뒤바꿔 서술 | "정규화 관점"처럼 기법을 관점으로 서술 |

## 2. 판정용 결정 트리

```text
선지가 설명하는 대상은?
├─ 추상적·전사적·사용자 관점 → 개념 모델
├─ Key·속성·관계·정규화, DBMS 독립 → 논리 모델
└─ 성능·저장구조·반정규화·인덱스 → 물리 모델
```

```text
선지에 "논리 스키마"가 등장하는가?
├─ 예 → 함정(3단계 스키마는 외부/개념/내부뿐)
└─ 아니오 → 외부/개념/내부 정의와 대조
```

각 선지를 먼저 O/X로 판정한 뒤 문제가 옳은 것을 묻는지 옳지 않은 것을 묻는지 확인해 정답을 고른다. 부정형("볼 수 없는 것은?")은 법리에 맞는 O 선지를 소거하고 법리에 어긋나는 X 선지를 선택한다.

## 3. 유사 사례 비교

| 사례 | 결정적 사실 | 적용 개념 | 결론 |
| --- | --- | --- | --- |
| "저장방식·인덱스를 정의한다" | 물리적 특성(저장구조) 언급 | 모델링 단계 | 물리 모델 |
| "성능향상 위해 반정규화 수행" 서술 위치 | 어느 단계 작업인지가 관건 | 모델링 단계 | 물리 모델(논리 모델 아님) |
| "조직 전체 통합 논리 구조" | 스키마 관점 서술 | 3단계 스키마 | 개념 스키마(모델링의 "개념 모델"과는 다른 축) |
| "업무 흐름 따라 데이터가 어떻게 조작되는가" | 데이터-프로세스 상호작용 | 모델링 관점 | 상관 관점(프로세스 관점과 구분) |

## 4. 반복 오답

| 선지 표현 | O/X | 틀린 이유 | 올바르게 고치면 |
| --- | :-: | --- | --- |
| 애플리케이션과 데이터 간 연계성을 높이면 모델이 안정적이다 | X | 연계성이 높을수록 사소한 변경에도 모델이 흔들림(방향 역전, D6) | 연계성을 낮춰야 비유연성이 줄어든다 |
| 논리적 모델링 단계에서 반정규화를 수행한다 | X | 반정규화는 물리적 모델링 단계의 작업(단계 혼동, D5) | 물리적 모델링 단계에서 반정규화를 수행한다 |
| 3층 스키마는 외부-논리-내부로 구성된다 | X | "논리" 스키마는 존재하지 않음(단계 혼동, D5) | 3층 스키마는 외부-개념-내부로 구성된다 |
| "정규화 관점"도 모델링 관점 중 하나다 | X | 정규화는 관점이 아니라 논리 모델링 기법(단계 혼동, D5) | 모델링 관점은 데이터/프로세스/상관 관점 세 가지뿐이다 |
| 개념적 모델링은 DBMS별로 종속적이다 | X | 개념적 모델링은 DBMS 독립적(반대 개념 적용, D2) | 개념적 모델링은 DBMS에 독립적이다 |

## 5. 자가 점검

표와 결정 트리를 가린 상태에서 답한다.

1. (핵심개념설명형) 데이터 모델링에서 지양해야 할 세 가지 유의사항은 무엇이며, 각각 어떤 원인에서 발생하는가?
2. (핵심개념설명형) 개념적·논리적·물리적 모델링 3단계는 각각 무엇을 관심 대상으로 삼는가?
3. (유사개념구별형) "개념 스키마"(3단계 스키마의 하나)와 "개념적 모델링"(모델링 3단계의 하나)은 이름이 비슷한데 어느 축에서 다른가?
4. (유사개념구별형) 프로세스 관점과 상관 관점을 가르는 결정적 차이는 무엇인가?
5. (사례판정형) "성능 향상을 위해 반정규화를 수행한다"는 서술은 개념/논리/물리 모델링 중 어디에 속하는가? 그 이유는?
6. (사례판정형) "조직 전체 관점에서 통합된 논리적 구조"라는 서술은 3단계 스키마 중 무엇을 가리키는가?
7. (반복오답교정형) "애플리케이션과 데이터 간 연계성을 높이면 모델이 안정적이다"는 왜 틀렸으며 어떻게 고쳐야 하는가?
8. (결정트리재현형) 아래 빈칸을 채우시오.

```text
선지가 설명하는 대상은?
├─ 추상적·전사적·________ 관점 → ________ 모델
├─ Key·속성·관계·________, DBMS 독립 → ________ 모델
└─ 성능·________·반정규화·________ → ________ 모델
```

<details>
<summary>자가 점검 정답</summary>

1. 중복(같은 데이터가 여러 곳에 반복 저장)·비유연성(애플리케이션과의 연계성이 높아 사소한 변경에도 모델이 흔들림)·비일관성(연관관계가 불명확해 일부 데이터만 변경)은 서로 다른 원인에서 발생하는 독립된 위험이며, "무엇 때문에 어떤 문제가 생기는가"를 판정 기준으로 삼는다.
2. 개념 모델은 추상적·전사적·사용자 관점의 핵심 업무 개념과 관계를, 논리 모델은 속성·식별자·관계·정규화를 DBMS 독립적으로, 물리 모델은 테이블·컬럼·자료형·인덱스 등 실제 구현을 다룬다는 것이 판정 기준이다.
3. "개념 스키마"는 3단계 스키마(외부/개념/내부)라는 저장·사용 구조 축에 속하고, "개념적 모델링"은 모델링 진행 순서(개념/논리/물리) 축에 속한다는 것이 판정 기준이며, 이름이 같아도 분류축이 다르면 혼동하지 않는다.
4. 프로세스 관점은 업무 처리 절차 자체("어떻게 처리하는가")를 보고, 상관 관점은 업무 흐름에 따라 데이터가 어떻게 조작되는지(데이터와 프로세스의 상호작용)를 본다는 것이 판정 기준이다.
5. 물리 모델링. 반정규화는 성능을 위해 저장구조를 조정하는 작업이므로 물리적 모델링 단계에서만 수행한다는 것이 판정 기준이다.
6. 개념 스키마. "조직 전체 통합 논리 구조"라는 표현이 나오면 외부·내부가 아니라 개념 스키마를 가리킨다는 것이 판정 기준이다.
7. 연계성이 높을수록 사소한 변경에도 모델이 흔들리는 비유연성의 원인이 되므로 틀렸다. "연계성을 낮춰야 비유연성이 줄어든다"로 고쳐야 한다.
8. 완성된 트리:

```text
선지가 설명하는 대상은?
├─ 추상적·전사적·사용자 관점 → 개념 모델
├─ Key·속성·관계·정규화, DBMS 독립 → 논리 모델
└─ 성능·저장구조·반정규화·인덱스 → 물리 모델
```
