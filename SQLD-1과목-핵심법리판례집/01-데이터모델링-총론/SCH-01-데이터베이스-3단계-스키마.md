# [SCH-01] 데이터베이스 3단계 스키마(외부/개념/내부)

> [!IMPORTANT]
> **핵심 법리:**
> ANSI/SPARC 3층 스키마는 외부 스키마(사용자·응용프로그램 관점의 개별 뷰), 개념 스키마(조직 전체 관점에서 통합된 논리적 구조), 내부 스키마(실제 데이터가 저장되는 물리적 구조) 3단계로만 구성된다. "논리"라는 이름의 스키마는 존재하지 않는다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지에 "논리 단계/논리 스키마"가 3층 스키마의 하나로 등장하면 함정이다. "실제 데이터 저장구조"라는 서술이 나오면 내부 스키마를 가리킨다.
>
> [!WARNING]
> **반복 오답:**
> 3층 스키마(외부/개념/내부)와 데이터 모델링 3단계(개념적/논리적/물리적, MOD-02)를 혼동해서 "논리"를 3층 스키마의 하나로 서술하는 함정, 내부 스키마와 물리적 모델링을 완전히 같은 개념으로 뒤섞는 함정.

## 1. 판시사항

- 데이터베이스 3단계 스키마(외부/개념/내부)는 각각 무엇을 나타내는가?
- 3단계 스키마와 개념적·논리적·물리적 데이터 모델링 3단계(MOD-02)는 이름이 비슷한데 어떻게 다른가?

## 2. 핵심 법리

> 데이터베이스는 ANSI/SPARC 3층 스키마 구조에 따라 외부 스키마(사용자·응용프로그램별로 필요한 데이터만 보이는 개별 뷰), 개념 스키마(조직 전체 관점에서 통합된 논리적 구조로, 모든 응용프로그램과 사용자가 공유하는 데이터베이스의 전체 청사진), 내부 스키마(디스크 등에 실제로 데이터가 저장되는 방식을 정의하는 물리적 구조)로 구성된다. 이 3단계에는 "논리"라는 이름의 스키마가 없으며, "논리"라는 용어는 데이터 모델링의 "논리적 모델링" 단계에서만 사용된다. 스키마 3단계(자료의 저장·사용 구조를 나누는 축)와 모델링 3단계(설계를 진행하는 시간 순서를 나누는 축)는 서로 다른 분류축이다.

## 3. 법리 적용 분기

```text
선지가 설명하는 스키마는?
│
├─ 사용자·응용프로그램 관점에서 필요한 데이터만 보는 개별 뷰
│  └─ 외부 스키마
│
├─ 조직 전체 관점에서 통합된 논리적 구조(전체 데이터베이스의 청사진)
│  └─ 개념 스키마
│
├─ 실제 데이터가 저장되는 물리적 저장구조(파일 형식, 저장 위치 등)
│  └─ 내부 스키마
│
└─ "논리 단계" 또는 "논리 스키마"라는 표현
   └─ 3층 스키마에 존재하지 않는 명칭
      (데이터 모델링 3단계의 "논리적 모델링"과 혼동을 유도한 함정)
```

## 4. 이 문제들이 유사한 이유

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 3층 스키마(외부/개념/내부)의 정의와, 여기에 "논리" 단계가 포함되지 않는다는 동일한 판단 규칙 |
| 공통 결정 사실 | 선지가 "사용자관점 개별 뷰"인지 "통합된 논리적 구조"인지 "실제 저장구조"인지, 아니면 존재하지 않는 "논리" 단계인지 |
| 반복되는 오답 구조 | 데이터 모델링 3단계(개념적/논리적/물리적)의 "논리"를 3층 스키마에 끼워넣는 함정 |
| 정답이 달라지는 조건 | "논리"라는 단어가 스키마 3단계를 가리키는지(존재하지 않음) 모델링 단계를 가리키는지(존재함) |

## 5. 대표 판례

### 사건 SCH-01-01

### 사실관계

"데이터베이스 3층 스키마에 해당되지 않는 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나는 "논리 단계"이다.

### 쟁점

3층 스키마(외부/개념/내부)에 "논리 단계"가 포함되는지가 쟁점이다. 이는 개념적·논리적·물리적 데이터 모델링 3단계(MOD-02)와의 명칭 혼동을 노린 함정이다.

### 적용 법리

ANSI/SPARC 3층 스키마는 외부/개념/내부 3단계로만 구성되며 "논리" 단계는 존재하지 않는다. "논리"라는 명칭은 데이터 모델링의 논리적 모델링 단계에서만 쓰이는 용어로, 스키마 3단계와는 별개의 분류축이다.

### 주문

**정답: ④**
