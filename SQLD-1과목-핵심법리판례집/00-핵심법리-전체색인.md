# 핵심 법리 전체 색인

## 핵심 법리 카드

시험 전에 이 카드만 반복해서 본다. 각 문제를 볼 때 "몇 번인지"가 아니라 "어떤 법리 ID인지"부터 떠올린다.

> **MOD-01** 데이터 모델링은 중복·비유연성·비일관성 세 가지를 지양해야 하며, 이 셋은 서로 다른 원인에서 발생한다.
>
> **MOD-02** 개념적 모델링은 추상적·전사적 사용자 관점, 논리적 모델링은 Key·속성·관계의 구체적 표현, 물리적 모델링은 성능·저장구조(반정규화 포함)를 다룬다.
>
> **MOD-03** 모델링 관점은 데이터 관점(What)·프로세스 관점(How)·상관 관점(데이터-프로세스 상호작용)으로 나뉜다.
>
> **SCH-01** 데이터베이스 3단계 스키마는 외부·개념·내부 스키마이며, 모델링의 개념·논리·물리 3단계와는 다른 분류축이다.
>
> **ENT-01** 엔터티는 업무상 관리할 필요가 있고 두 개 이상의 인스턴스를 가질 수 있는 독립적인 대상이며, 속성 1개 이상과 관계 1개 이상을 가져야 한다.
>
> **ENT-02** 엔터티는 발생시점 기준(기본/중심/행위)과 유무형 기준(유형/개념/사건)이라는 서로 다른 두 축으로 분류된다.
>
> **ATTR-01** 속성은 하나의 인스턴스에 대해 하나의 속성값만 가지는 것이 원칙이다(다중값이면 정규화 대상).
>
> **ATTR-02** 속성은 기본속성(요구사항에서 직접 도출)·설계속성(설계 중 새로 정의)·파생속성(다른 속성으로부터 계산)으로 나뉜다.
>
> **REL-01** 관계는 두 엔터티 사이에 조합되는 정보가 있고 업무적으로 영향을 주고받을 때 성립하며, 필수참여/선택참여는 반드시 관계마다 별도로 판단한다.
>
> **ERD-01** 표기법마다 기호가 다르다 — IE/Crow's Foot은 까치발(2개 이상)과 O(선택), Barker는 o(NULL허용)·*(NULL비허용)·#(주식별자)로 표시하며 NULL 여부까지 표현하지만 IE는 표현하지 않는다.
>
> **ID-01** 주식별자는 유일성·최소성·불변성·존재성을 충족해야 한다.
>
> **ID-02** 식별관계는 부모의 식별자를 자식이 주식별자의 일부로 포함(실선)하고, 비식별관계는 일반속성으로만 포함(점선)한다.
>
> **ID-03** 본질식별자는 업무에서 자연발생하는 식별자이고, 인조식별자는 대체 목적으로 인위적으로 만든 식별자다 — 둘의 장단점은 정반대로 대응된다.
>
> **NORM-01** 정규화의 목적은 삽입·갱신·삭제 이상현상 제거이며 데이터 무결성 확보이지, 조회 성능 향상이 아니다.
>
> **NORM-03** 제2정규형은 주식별자의 일부에만 종속되는 부분함수종속을 제거한다(복합식별자에서만 발생 가능).
>
> **NORM-04** 제3정규형은 일반속성끼리 종속되는 이행함수종속을 제거한다.
>
> **PERF-01** 반정규화는 조회 성능을 위해 무결성 위험을 감수하고 중복을 허용하는 기법(병합/분할/추가)이며, 정규화와 목적이 반대다.
>
> **NULL-02** NULL과 일반 비교 연산의 결과는 UNKNOWN이며 WHERE는 TRUE만 통과시키므로 `= NULL`이 아닌 `IS NULL`을 써야 한다.
>
> **NULL-03** NULL이 포함된 산술 연산의 결과는 항상 NULL이다.
>
> **NULL-04** 집계함수는 NULL을 제외하고 계산하지만, `COUNT(*)`만은 예외적으로 NULL이 있는 행도 센다.

## 표 사용법

- "유사 판례 수"는 대표 판례를 제외하고 같은 법리로 묶인 문제의 개수다. 0인 항목은 현재 PDF 자료에서 대표 판례 1건만 확인되었다는 뜻이며, 임의로 유사 문제를 지어내지 않았다는 표시다.
- 실제 문제 목록은 [00-문제출처-역색인.md](./00-문제출처-역색인.md)에서, 모의고사 단위로는 [99-모의고사-역색인/](./99-모의고사-역색인/)에서 확인한다.
