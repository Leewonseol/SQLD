# 03 속성과 도메인

기본 학습은 아래 비교표와 결정 트리로 진행한다. 상세 근거와 기출 해설이 필요할 때만 하단 "상세 법리 파일" 링크를 연다.

## 1. 핵심 개념 비교표

### 기본속성·설계속성·파생속성 (생성 방식 축)

| 구분 | 기본속성 | 설계속성 | 파생속성 |
| --- | --- | --- | --- |
| 생성 방식 | 업무에서 원천적으로 입력 | 업무 규칙상 새로 정의 | 다른 속성을 계산·집계·가공 |
| 사례 | 고객ID, 생년월일, 계좌번호 | 고객구분코드(DV01, DV02) | 총주문금액(수량×단가), 근속연수, 부서별 인원수 |
| 갱신 | 원본 직접 변경 | 규칙에 따라 관리 | 원본 변경 시 재계산 필요 |
| 반복 함정 | 계산값을 기본속성으로 분류 | 계산값을 설계속성으로 분류 | "갱신 불필요"라고 서술(D1) |

### 단일속성·복합속성·다중값속성 (구조 축, 위 축과 독립)

| 구분 | 단일(단순)속성 | 복합속성 | 다중값속성 |
| --- | --- | --- | --- |
| 구조 | 더 이상 분해 불필요 | 세부 항목으로 분해 가능 | 한 인스턴스가 여러 값을 동시에 보유 |
| 사례 | 사번, 이름 | 주소(시/구/동/번지) | 취미(다중값 — 1차정규화 대상) |
| 반복 함정 | — | 다중값속성·파생속성과 혼동 | 단일값 원칙 위반, 정규화 대상 |

### 도메인

| 요소 | 내용 |
| --- | --- |
| 자료형 | 숫자·문자·날짜 등 |
| 길이 | 최대 자릿수·바이트 수 |
| 허용값 | 코드값 목록, 범위 |
| 제약조건 | NULL 허용 여부, 체크 조건 등 |

도메인은 "속성이 무엇인가"(정의)가 아니라 "그 속성에 어떤 값이 들어갈 수 있는가"를 다루는 개념이다.

## 2. 판정용 결정 트리

```text
속성값이 어떻게 만들어지는가?
├─ 업무에서 원천적으로 입력 → 기본속성
├─ 업무 규칙을 위해 설계 중 새로 정의(코드값 등) → 설계속성
└─ 다른 속성을 계산·집계·가공 → 파생속성(원본 변경 시 재계산 필요)
```

```text
속성값의 구조는?
├─ 더 이상 분해 불필요 → 단일속성
└─ 하위 항목으로 분해 가능 → 복합속성
   (값 개수·계산 여부와는 다른 축)
```

각 선지를 먼저 O/X로 판정한 뒤 문제가 O를 묻는지 X를 묻는지 확인해 정답을 선택한다. 여러 속성을 한 번에 분류하는 종합형 문제는 각 속성을 "기본/설계/파생" 축과 "단일/복합" 축으로 각각 독립적으로 판정한다(두 축은 동시에 적용되지만 서로 다른 질문).

## 3. 유사 사례 비교

| 사례 | 생성 방식 | 판정 |
| --- | --- | --- |
| 고객ID | 업무에서 원천 입력 | 기본속성 |
| 고객구분코드 | 업무 규칙상 새로 정의 | 설계속성 |
| 총주문금액 | 수량×단가 | 파생속성 |
| 근속연수 | 기준일−입사일 | 파생속성 |
| 부서별 인원수 | 인원 집계 | 파생속성 |
| 주소 | 시/구/동/번지로 분해 가능 | 복합속성(생성방식 축과 무관) |

## 4. 반복 오답

| 선지 표현 | O/X | 틀린 이유 | 올바르게 고치면 |
| --- | :-: | --- | --- |
| 파생속성은 원본이 바뀌어도 별도 갱신이 필요 없다 | X | 파생속성은 원본 변경 시 재계산·갱신 필요(정의 바꿔치기, D1) | 파생속성은 원본이 바뀌면 재계산·갱신해야 한다 |
| 하나의 속성은 다중값을 가질 수 있다 | X | 속성은 단일값 원칙을 따름(범위 과장, D4) | 하나의 속성은 하나의 값만 가진다(다중값이면 별도 엔터티로 분리) |
| 속성 명명 시 의미가 길면 임의로 약어를 사용해도 된다 | X | 협의되고 공식화된 약어만 허용(범위 과장, D4) | 속성명은 협의된 공식 약어만 사용한다 |
| 일반속성은 발생방식(기본/설계/파생) 분류의 하나다 | X | 일반속성은 PK/FK 포함 여부에 따른 구성방식 분류(분류축 혼동, D5) | 일반속성은 발생방식이 아니라 엔터티 구성방식 분류에 속한다 |
| 복합속성은 계산으로 생성된 속성이다 | X | 복합속성은 "구조를 나눌 수 있는가"의 문제, 계산 여부는 파생속성(분류축 혼동, D5) | 복합속성은 하위 항목으로 분해 가능한 구조를 가진 속성이다 |

## 5. 자가 점검

표와 결정 트리를 가린 상태에서 답한다.

1. (핵심개념설명형) 파생속성의 정의를 한 문장으로 설명하고, 원본 속성이 바뀌면 어떻게 처리해야 하는지 말하시오.
2. (핵심개념설명형) 도메인이 무엇을 다루는 개념인지, 속성의 정의와 어떻게 다른지 한 문장으로 설명하시오.
3. (유사개념구별형) 복합속성과 다중값속성을 구별하는 결정적 기준은 무엇인가?
4. (유사개념구별형) 설계속성과 파생속성을 가르는 결정적 기준은 무엇인가?
5. (사례판정형) "총주문금액 = 수량×단가"는 어떤 속성으로 분류되며, 그 판정 기준은 무엇인가?
6. (사례판정형) "주소"를 "시/구/동/번지"로 나눌 수 있다면 이는 어떤 속성으로 분류되는가?
7. (반복오답교정형) "파생속성은 원본이 바뀌어도 별도 갱신이 필요 없다"는 서술의 어디가 왜 틀렸는지 한 문장으로 고치시오.
8. (결정트리재현형) 아래 빈칸을 채우시오.

```text
속성값이 어떻게 만들어지는가?
├─ 업무에서 원천적으로 입력 → (        )
├─ 업무 규칙을 위해 설계 중 새로 정의(코드값 등) → (        )
└─ 다른 속성을 계산·집계·가공 → (        )(원본 변경 시 (        ) 필요)
```

<details>
<summary>자가 점검 정답</summary>

1. 파생속성은 다른 속성을 계산·집계·가공해서 만들어지는 속성이며, 원본 속성이 변경되면 재계산·갱신해야 한다.
2. 도메인은 속성이 무엇인지(정의)가 아니라 그 속성에 어떤 값(자료형·길이·허용범위·제약조건)이 들어갈 수 있는지를 다루는 개념이다.
3. 복합속성은 "구조를 하위 항목으로 나눌 수 있는가"의 문제이고, 다중값속성은 "하나의 인스턴스가 값을 몇 개 동시에 가지는가"(단일값 원칙 위반)의 문제다 — 서로 다른 축이다.
4. 설계속성은 업무 규칙을 정형화하려고 설계 과정에서 새로 정의한 코드값(예: 구분코드)이고, 파생속성은 다른 속성을 계산·집계해서 만든 값이다 — "새로 정의했는가"와 "계산해서 나왔는가"의 차이다.
5. 파생속성이다. 수량과 단가라는 다른 속성을 계산(곱)해서 만든 값이기 때문이다.
6. 복합속성이다. 하나의 속성값이 시/구/동/번지라는 하위 항목으로 의미 있게 분해되기 때문이다.
7. 틀린 부분은 "갱신이 필요 없다"이다. 파생속성은 원본이 변경되면 재계산·갱신해야 하므로, "원본이 바뀌면 재계산·갱신해야 한다"로 고쳐야 한다.
8. 순서대로 기본속성 / 설계속성 / 파생속성 / 재계산·갱신

</details>

| 선지 핵심 주장 | 내 판정 | 정답 | 결정적 이유 |
| --- | :-: | :-: | --- |
| ① 기본속성이다 | | X | 총주문금액은 원초적으로 입력되는 값이 아니라 계산 결과 |
| ② 파생속성이다 | | O | 수량×단가라는 계산 규칙으로 생성되는 전형적 파생속성 |
| ③ 설계속성이다 | | X | 설계속성은 업무 규칙을 위한 코드값이지 계산 결과가 아님 |
| ④ 일반속성이다 | | X | 일반속성은 발생방식이 아니라 PK/FK 포함 여부에 따른 구성방식 분류 |

<details>
<summary>선지별 정답</summary>

| 선지 | O/X | 이유 | 틀린 경우 올바른 문장 |
| --- | :-: | --- | --- |
| ① | X | 기본속성은 고객ID·생년월일처럼 업무에서 원천적으로 입력되는 값이어야 함 | "고객ID, 주문일자"처럼 원초적 입력값이어야 기본속성이다 |
| ② | O | 다른 속성(수량, 단가)을 계산해서 생성되고 검색 성능을 위해 저장하는 파생속성의 전형적 사례 | 해당 없음 |
| ③ | X | 설계속성은 "구매등급코드"처럼 업무 규칙을 위해 새로 정의한 코드값이어야 함 | "구매등급코드"처럼 코드값이어야 설계속성이다 |
| ④ | X | 일반속성은 발생방식 분류가 아니라 PK/FK 포함 여부에 따른 엔터티 구성방식 분류 | 발생방식 분류 문제에는 기본/설계/파생 중 하나로 답해야 한다 |

</details>
