# [ATTR-01] 속성의 정의와 특징(단일값 원칙), 명명규칙

> [!IMPORTANT]
> **핵심 법리:**
> 속성(Attribute)은 엔터티의 인스턴스를 설명하는 더 이상 분리되지 않는 최소 단위의 정보 항목이며, 반드시 하나의 속성은 하나의 속성값만 가져야 한다(단일값 원칙). 하나의 속성이 여러 개의 값을 동시에 가지면 1차 정규화 대상이다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지가 "속성이 다중값을 가질 수 있다"고 서술하면 무조건 틀린 설명이다. 속성 명명규칙에서 "의미가 길면 임의로 약어를 사용해도 된다"는 서술도 틀린 설명이다 — 협의되고 공식화된 약어만 허용된다.
>
> [!WARNING]
> **반복 오답:**
> 속성이 다중값을 가질 수 있다고 서술하는 함정(D4 범위 과장), 속성 명명 시 임의 약어 사용을 허용하는 것처럼 서술하는 함정(D4), 엔터티(관리 대상)를 속성(설명 항목)의 정의로 서술하는 함정(D1).

## 1. 판시사항

- 속성의 정의는 무엇이며, 속성과 속성값의 관계는 어떻게 성립하는가?
- 속성 명명규칙에서 지켜야 할 원칙은 무엇인가?

## 2. 핵심 법리

> 속성은 업무에서 관리하고자 하는 인스턴스의 성질·특징 중 의미상 더 이상 분리되지 않는 최소 단위의 정보 항목이다. 하나의 속성은 반드시 하나의 속성값만을 가져야 하며, 여러 값을 가지는 경우는 정상적인 속성이 아니라 1차 정규화(반복 그룹 제거)의 대상이다. 속성명은 업무에서 사용하는 용어를 사용하고, 전사적으로 협의·표준화된 약어만 허용되며 임의의 약어 사용은 금지된다.

## 3. 법리 적용 분기

```text
선지가 속성에 관해 서술하는 내용은?
│
├─ "하나의 속성은 하나의 속성값만 가진다"
│  └─ 옳음(단일값 원칙)
│
├─ "하나의 속성이 여러 개의 값을 가질 수 있다"
│  └─ 틀림 — 1차 정규화 대상이지 정상적인 속성 상태가 아님
│
├─ "속성명은 업무에서 사용하는 용어, 협의된 약어만 사용"
│  └─ 옳음
│
└─ "의미가 길면 임의로 약어를 사용해도 된다"
   └─ 틀림 — 임의 약어 금지
```

## 4. 이 문제들이 유사한 이유

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 속성의 정의(최소 정보 단위, 단일값 원칙)와 명명규칙을 판단하는 동일한 규칙 |
| 공통 결정 사실 | 선지가 "속성은 하나의 값만 가진다"는 원칙을 지키는지, 아니면 다중값·임의약어처럼 원칙을 위반하는지 |
| 반복되는 오답 구조 | 속성이 다중값을 가질 수 있다고 과장(D4), 임의 약어 사용을 허용하는 것처럼 서술(D4) |
| 정답이 달라지는 조건 | 선지가 단일값 원칙을 그대로 지키는 서술인지, "여러 값" 또는 "임의로"라는 단어로 원칙을 깨는 서술인지 |

### 사건 ATTR-01-01

### 사실관계

"속성의 특징으로 옳지 않은 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나는 "하나의 속성은 다중값을 가질 수 있다"이다.

### 쟁점

속성이 다중값을 가질 수 있는지 여부가 쟁점이다.

### 적용 법리

속성은 반드시 하나의 속성값만을 가져야 하는 단일값 원칙이 적용된다. 다중값을 갖는 경우는 정상 상태가 아니라 1차 정규화의 대상이므로, "다중값을 가질 수 있다"는 서술은 속성의 특징으로 옳지 않다.

### 주문

**정답: ②**

### 판결이유

```text
문제의 결정적 사실: 선지 ②가 "하나의 속성은 다중값을 가질 수 있다"고 서술함
→ 적용되는 핵심 법리: 속성은 반드시 하나의 속성값만 가져야 한다(단일값 원칙)
→ 정답 선지: ②(단일값 원칙을 위반한 서술이므로 옳지 않은 특징)
```

## 9. 출제자가 바꾸는 사실

- "하나의 속성은 다중값을 가질 수 있다"로 단일값 원칙을 뒤집기
- 속성 명명규칙에서 임의 약어 사용을 허용하는 것처럼 서술
- 엔터티의 정의(집합적·포괄적 대상)를 속성의 정의로 바꿔치기

## 10. 시험용 한 줄 법리

> 속성은 "더 이상 쪼갤 수 없는 최소 정보 단위"이며 "반드시 하나의 값"만 가진다 — 다중값이 보이면 무조건 오답.
