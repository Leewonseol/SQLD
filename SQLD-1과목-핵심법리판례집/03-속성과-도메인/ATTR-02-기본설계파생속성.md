# [ATTR-02] 기본속성·설계속성·파생속성 구분

> [!IMPORTANT]
> **핵심 법리:**
> 속성은 발생 방식에 따라 업무 자체에서 자연스럽게 도출되는 기본속성, 업무를 규칙화·정형화하기 위해 설계 과정에서 새로 만들어지는 설계속성, 다른 속성의 값을 계산·가공해서 만들어지는 파생속성으로 나뉜다. 파생속성은 원본 데이터가 변경되면 함께 재계산·갱신되어야 한다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지에 "계산", "집계", "자동 생성", "검색 속도를 위해 미리 저장" 같은 표현이 있으면 파생속성이다. "코드값", "구분값(DV01, DV02 등)"처럼 업무 규칙을 위해 새로 정의한 값이면 설계속성이다. 원본 업무 데이터(고객ID, 생년월일, 계좌번호 등)를 그대로 관리하는 것이면 기본속성이다.
>
> [!WARNING]
> **반복 오답:**
> 파생속성을 "데이터 변경 시 별도 갱신이 필요 없다"고 서술하는 함정(실제로는 갱신 필요, D1 정의 바꿔치기), "일반속성"을 특성(발생방식) 분류의 하나처럼 서술하는 함정(일반속성은 PK/FK 포함 여부에 따른 엔터티 구성방식 분류이지 발생방식 분류가 아니다, D5 분류축 혼동), 파생속성(나이, 부서별 인원수)을 기본속성으로 잘못 분류하는 함정.

## 1. 판시사항

- 기본속성·설계속성·파생속성은 각각 어떤 기준으로 구분되며, 대표적인 예시는 무엇인가?
- 파생속성은 원본 데이터가 변경될 때 별도의 갱신이 필요한가?

## 2. 핵심 법리

> 속성은 발생 방식에 따라 **기본속성**(업무로부터 도출되는 가장 원초적인 속성, 예: 고객ID·생년월일·계좌번호), **설계속성**(업무를 규칙화하기 위해 새로 정의하는 속성, 예: 코드성 구분값), **파생속성**(다른 속성이나 계산 규칙에 의해 생성되는 속성, 예: 총주문금액=수량×단가, 나이, 부서별 인원수)으로 구분된다. 파생속성은 원본 속성이 변경되면 정합성을 위해 재계산·갱신이 필요하며 "갱신이 필요 없다"는 서술은 파생속성의 정의를 위반한다. 한편 "일반속성"은 이 발생방식 분류가 아니라 PK/FK 포함 여부에 따른 엔터티 구성방식 분류이므로 혼동하면 안 된다.

## 3. 법리 적용 분기

```text
속성이 어떻게 만들어졌는가?
│
├─ 업무 자체에서 자연스럽게 도출되는 원초적 데이터
│  └─ 기본속성 (예: 고객ID, 생년월일, 계좌번호)
│
├─ 업무 규칙을 정형화하기 위해 설계 단계에서 새로 정의
│  └─ 설계속성 (예: 코드성 구분값 DV01, DV02)
│
└─ 다른 속성 값을 계산·가공해서 생성(집계, 자동계산, 검색성능용 저장)
   └─ 파생속성 (예: 총주문금액=수량×단가, 나이, 부서별 인원수)
      └─ 원본 속성 변경 시 재계산·갱신 필요(갱신 불필요 서술은 오답)

주의: "일반속성"은 이 3분류가 아니라 PK/FK 포함 여부에 따른
      엔터티 구성방식 분류 — 발생방식 선지에 등장하면 분류축 오류
```

## 4. 이 문제들이 유사한 이유

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 기본속성·설계속성·파생속성을 발생 방식(원초적 도출/설계상 정의/계산 가공)으로 구분하는 동일한 판단 규칙 |
| 공통 결정 사실 | 선지·사례에 "계산·집계·자동생성" 키워드가 있는지, "코드값·구분값"인지, "원초적 업무 데이터"인지 |
| 반복되는 오답 구조 | 파생속성을 "갱신 필요 없다"고 서술(D1), 일반속성을 발생방식 분류로 혼동(D5), 파생속성을 기본속성으로 잘못 분류(D1) |
| 정답이 달라지는 조건 | 속성 값이 다른 속성의 계산 결과인지(파생) 아니면 원본 그대로인지(기본)에 따라 정답이 갈린다 |

## 5. 대표 판례

- 보조 법리 ID: 없음

### 사실관계

주문상세 상황에서 "총주문금액은 수량×단가로 자동 생성되며, 검색 시 빠른 결과를 위해 별도로 저장한다"는 설명이 주어지고 이 속성의 분류를 묻는다.

### 쟁점

총주문금액이 다른 속성(수량, 단가)의 계산 결과로 만들어지는 속성인지, 원초적으로 입력되는 기본속성인지가 쟁점이다.

### 적용 법리

총주문금액은 수량과 단가라는 다른 속성의 값을 계산해서 만들어지므로 파생속성이며, 검색 성능을 위해 미리 저장해두는 것도 파생속성의 전형적 활용 방식이다.

### 주문

**정답: ②(파생속성)**

### 판결이유

```text
문제의 결정적 사실: 총주문금액이 "수량×단가로 자동 생성"되고 "검색 시 빠른 결과를 위해 저장"된다고 서술됨
→ 적용되는 핵심 법리: 다른 속성의 값을 계산·가공해서 만들어지는 속성은 파생속성이다
→ 정답 선지: ②(파생속성)
```

### page_06 문제04 상세 판정 (표본감사 A02)

이 문제는 단순 판독 오류가 아니라 인쇄 정답과 인쇄 해설의 설명 범위가 어긋나는 사례이므로, 세 층위(인쇄 정답 / 인쇄 해설 / 핵심 법리 판정)를 분리해서 기록한다.

| 판단 기준 | 결론 | 근거 |
| --- | --- | --- |
| 인쇄 정답 | ①, ③ (근속연수, 부서별인원수) | 페이지 하단 정답표에 "04①,③"으로 인쇄됨(고배율 재확인 완료) |
| 인쇄 해설 | ③만 설명 | "기본 속성은 요구사항에서 직접 도출된 정보이며, 부서별인원수는 부서 데이터를 집계해 만들어진 파생 속성이다."라고만 서술하고 ①(근속연수)은 별도로 언급하지 않음 |
| 핵심 법리 판정 | ①, ③ 모두 파생속성(=둘 다 기본속성 아님) | 근속연수는 "기준일자 − 입사일자"라는 다른 속성 간 계산으로 산출되는 값이므로 ATTR-02의 파생속성 정의(다른 속성으로부터 계산되어 만들어지는 속성)에 그대로 부합한다. 부서별인원수도 동일하게 집계로 산출되는 파생속성이다. 따라서 핵심 법리를 엄격하게 적용해도 인쇄 정답(①,③)과 결론이 일치한다 |
| 최종 감사 상태 | PASS | 인쇄 정답·핵심 법리 판정이 서로 일치하고, 판례집(위 유사판례 표)이 "해설이 ③만 설명하고 ①의 근거는 문제집에 명시되지 않았다"는 사실을 이미 정확히 병기하고 있으므로 판례집 자체의 오류는 아니다 |

> **법리상 판정:**
> 핵심 법리를 엄격하게 적용하면 근속연수와 부서별 인원수는 모두 기존 속성에서 계산·집계되는 파생속성으로 판단된다.
>
> **출처 상태:**
> 인쇄 정답과 해설 범위가 일치하지 않아(정답은 ①,③ 두 개인데 해설은 ③만 설명) 문제집 내부의 해설 누락 가능성이 있다. 원문의 인쇄 정답을 임의로 수정하지 않았으며, 판례집은 이 불일치를 그대로 병기한다.

## 8. 구별 판례

| 구별 요소 | 이 사건 | 비교 사건 | 답이 달라지는 이유 |
| --- | --- | --- | --- |
| 판단 대상 | 속성의 발생방식(기본/설계/파생) | ATTR-03의 속성 구조(단일/복합) | ATTR-02는 "이 속성값이 어떻게 만들어졌는가"를 묻고, ATTR-03은 "이 속성이 더 작은 속성으로 쪼개지는가"를 묻는다. 파생속성이면서 동시에 복합속성일 수도 있어 두 분류축은 서로 배타적이지 않다 |

## 9. 출제자가 바꾸는 사실

- 파생속성을 "갱신이 필요 없다"고 반대로 서술
- 일반속성(PK/FK 구성방식 분류)을 발생방식 분류 목록에 섞어 넣기
- 계산·집계로 만들어지는 속성(나이, 부서별 인원수)을 기본속성으로 잘못 분류
- 코드성 구분값(설계속성)을 기본속성이나 파생속성으로 혼동시키기

## 10. 시험용 한 줄 법리

> "계산해서 나온 값"이면 파생, "업무 규칙을 위해 새로 정의한 코드값"이면 설계, "원초적으로 입력되는 값"이면 기본이다.
