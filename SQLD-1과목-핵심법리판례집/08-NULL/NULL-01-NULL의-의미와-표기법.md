# [NULL-01] NULL의 의미와 표기법

> [!IMPORTANT]
> **핵심 법리:**
> NULL은 "값이 존재하지 않거나 아직 정해지지 않은 상태"를 나타내는 상태값이며, 숫자 0이나 공백(빈 문자열)과는 전혀 다른 개념이다. ERD 표기법마다 NULL 허용 여부를 표현하는 방식이 다른데, Barker 표기법은 o(허용)·*(비허용) 기호로 명시하지만 IE(정보공학) 표기법은 애초에 NULL 허용 여부를 표기하는 관례가 없다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지가 "NULL이 무엇인가"를 정의하는 서술인지, 아니면 "어느 표기법이 NULL 여부를 표현/구분할 수 있는가"를 묻는 서술인지 구분한다. NULL을 값(0, 공백)으로 취급하면 오답이고, IE 표기법이 NULL 여부를 확인할 수 있다고 하면 오답이다.
>
> [!WARNING]
> **반복 오답:**
> "NULL은 0과 같다", "NULL은 공백(space)과 같다"는 값·상태 혼동 함정, "IE 표기법도 NULL 허용 여부를 표시/확인할 수 있다"는 표기법 혼동 함정, Barker의 *(NULL 비허용)과 #(주식별자) 기호의 의미를 뒤바꾸는 함정.

## 1. 판시사항

- NULL의 정의와 성질은 무엇이며, 숫자 0이나 공백과 어떻게 다른가?
- ERD 표기법(IE vs Barker)에서 NULL 허용 여부는 어떻게 표시되며, 어느 표기법이 이를 표현하지 못하는가?
- NOT NULL(NULL 비허용) 속성은 SQL 입력 시 어떤 제약을 받는가?

## 2. 핵심 법리

> NULL은 "아직 알 수 없는 값" 또는 "존재하지 않는 값"을 나타내는 상태이며, 숫자 0이나 문자열의 공백(' ')과는 완전히 다른 개념이다 — 0과 공백은 그 자체로 하나의 값이지만 NULL은 값이 없는 상태이다. ERD 표기 측면에서 Barker 표기법은 속성 앞에 o(NULL 허용), *(NULL 비허용), #(주식별자) 기호를 붙여 NULL 여부를 명시적으로 표현하지만, IE 표기법은 속성 목록에 NULL 허용 여부를 표기하는 관례 자체가 없으므로 IE로 그려진 ERD만 보고는 NULL 허용 여부를 판단할 수 없다. NOT NULL로 지정된 속성은 SQL INSERT 시 반드시 값을 입력해야 하며 생략할 수 없다.

## 3. 법리 적용 분기

```text
NULL 관련 선지가 다루는 대상은?
│
├─ NULL의 값·상태 자체를 정의하는 서술
│  ├─ "0/공백과 동일하다" → 오답(D9 값·상태 혼동)
│  └─ "존재하지 않거나 아직 모르는 상태다" → 옳은 설명
│
└─ ERD 표기법에서 NULL 허용 여부 표기
   ├─ Barker 표기법
   │  ├─ o 기호 → NULL 허용
   │  ├─ * 기호 → NULL 비허용(NOT NULL)
   │  └─ # 기호 → 주식별자(NULL 여부와는 별개 개념)
   └─ IE(정보공학) 표기법
      └─ NULL 허용 여부를 표기하는 기호 자체가 없음(그림만으로 확인 불가)
```

### 사실관계

"NULL에 대한 설명 중 옳지 않은 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나는 "NULL은 숫자 0과 동일하게 취급된다"는 서술이다.

### 쟁점

NULL을 실제 값인 숫자 0과 동일시할 수 있는지가 쟁점이다.

### 적용 법리

NULL은 값이 존재하지 않는 상태를 나타내고, 0은 그 자체로 실제 숫자값이므로 두 개념은 서로 다르다. "NULL은 0과 동일하게 취급된다"는 서술은 NULL의 정의를 왜곡한 것이므로, "옳지 않은 것"을 고르는 이 문제의 정답이 된다.

## 9. 출제자가 바꾸는 사실

- NULL을 숫자 0이나 공백(빈 문자열)과 동일시하는 서술로 바꿔치기(D9)
- "IE 표기법도 NULL 허용 여부를 표시/확인할 수 있다"고 표기법의 한계를 뒤집어 서술
- Barker 표기법의 *(NULL 비허용)과 #(주식별자) 기호의 의미를 서로 바꿔치기
- NOT NULL 속성인데도 "INSERT 시 값을 생략할 수 있다"고 서술
