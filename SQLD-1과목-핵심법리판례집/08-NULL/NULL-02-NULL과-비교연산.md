# [NULL-02] NULL과 비교연산·3값 논리(UNKNOWN)

> [!IMPORTANT]
> **핵심 법리:**
> NULL은 "값이 없는 상태"이므로 일반 비교연산자(`=`, `<>`, `>` 등)로 비교할 수 없다. `COL = NULL`은 참(TRUE)도 거짓(FALSE)도 아닌 UNKNOWN이 되며, SQL의 WHERE 절은 TRUE인 행만 통과시키므로 이런 조건은 항상 결과가 없다(0건). NULL 여부를 판단할 때는 반드시 `IS NULL` / `IS NOT NULL`을 써야 한다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 선지가 `= NULL`과 `IS NULL`을 같은 것처럼 서술하는지 확인한다. 이 둘은 결과가 다르다 — `IS NULL`은 NULL 여부를 정상적으로 판별하지만 `= NULL`은 항상 UNKNOWN이라 어떤 행도 반환하지 않는다.
>
> [!WARNING]
> **반복 오답:**
> "`WHERE COL = NULL`과 `WHERE COL IS NULL`은 같은 조건이다"라는 함정, `= NULL`의 결과를 FALSE라고 단정하는 함정(정확히는 UNKNOWN), NULL 비교 결과를 산술연산처럼 "NULL"이라는 값으로 서술하는 함정(비교연산의 결과는 값이 아니라 진리값 UNKNOWN이다).

## 1. 판시사항

- NULL이 포함된 비교연산의 결과는 무엇이며, 왜 `WHERE COL = NULL`은 항상 결과가 없는가?
- `IS NULL`과 `= NULL`은 왜 같은 조건이 아닌가?

## 2. 핵심 법리

> SQL은 TRUE·FALSE·UNKNOWN의 3값 논리를 사용한다. NULL은 "정해지지 않은 값"이므로 다른 어떤 값과 비교해도(심지어 NULL끼리 비교해도) 참/거짓을 판정할 수 없고 결과는 UNKNOWN이 된다. WHERE 절은 조건이 TRUE인 행만 통과시키므로, UNKNOWN이 되는 `COL = NULL` 조건은 어떤 행도 반환하지 못한다. 따라서 NULL 여부를 확인하려면 비교연산자가 아니라 전용 연산자인 `IS NULL` / `IS NOT NULL`을 사용해야 한다.

## 3. 법리 적용 분기

```text
NULL이 비교연산에 관여하는가?
│
├─ "= NULL", "<> NULL" 등 일반 비교연산자 사용
│  └─ 결과 UNKNOWN(WHERE 절 통과 못함, 0건)
│
└─ "IS NULL", "IS NOT NULL" 전용 연산자 사용
   └─ NULL 여부를 정상적으로 판별(TRUE/FALSE)
```

### 사실관계

"NULL 연산에 대한 설명 중 옳지 않은 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나는 "`WHERE COL IS NULL` 조건은 `WHERE COL = NULL` 조건과 같다"는 서술이다.

### 쟁점

`IS NULL`과 `= NULL`이 동일한 결과를 내는 조건인지가 쟁점이다.

### 적용 법리

`COL = NULL`은 비교연산자에 NULL이 피연산자로 들어간 것이므로 결과가 항상 UNKNOWN이 되어 WHERE 절을 통과하는 행이 없다. 반면 `COL IS NULL`은 NULL 여부를 판별하는 전용 연산자이므로 NULL인 행을 정상적으로 찾아낸다. 따라서 두 조건은 결과가 다르며, "같다"는 서술은 틀린 설명이다.

## 9. 출제자가 바꾸는 사실

- `WHERE COL = NULL`과 `WHERE COL IS NULL`을 같은 조건처럼 교환해서 서술
- `= NULL`의 결과를 UNKNOWN이 아니라 FALSE로 단정
- 비교연산의 결과(UNKNOWN, 진리값)를 산술연산의 결과(NULL, 값)와 혼동해서 서술

## 10. 시험용 한 줄 법리

> `COL = NULL`은 항상 UNKNOWN이라 결과가 없다 — NULL을 찾으려면 반드시 `IS NULL`을 쓴다.
