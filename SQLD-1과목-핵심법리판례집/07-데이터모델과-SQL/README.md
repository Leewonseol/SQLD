# 07 데이터 모델과 SQL

기본 학습은 아래 비교표와 결정 트리로 진행한다. 상세 근거와 기출 해설이 필요할 때만 하단 "상세 법리 파일" 링크를 연다.

## 1. 핵심 개념 비교표

### 조인·트랜잭션·반정규화 핵심 판단

| 주제 | 핵심 판단 |
| --- | --- |
| 조인 | 필요한 정보가 여러 테이블에 분산되어 있는가(정보 통합 조회가 목적, 성능 향상이 목적 아님) |
| 트랜잭션 | 여러 DML이 하나의 논리적 업무 단위인가(정합성 보장이 목적, 성능 향상이 목적 아님) |
| 반정규화 | 성능 개선 이익이 정합성 위험보다 큰가 |

### 트랜잭션 처리

| 상황 | 처리 |
| --- | --- |
| 모든 작업 성공 | COMMIT |
| 일부 작업 실패 | ROLLBACK |
| 중간 복구 지점 필요 | SAVEPOINT |

### 정규화 vs 반정규화

| 구분 | 정규화 | 반정규화 |
| --- | --- | --- |
| 목적 | 중복과 이상현상 감소, 무결성 확보 | 조회 성능 개선 |
| 위험 | 조인 증가로 조회 성능 저하 가능 | 중복·정합성 위험 |
| 적용 시점 | 논리적 모델링(기본 원칙) | 물리적 모델링(성능 문제 확인 후 선택) |
| 대표 기법 | — | 테이블 병합, 테이블 분할(수직/수평), 중복 컬럼 추가, 중복 관계 추가 |

⚠️ 함수종속을 고려한 테이블 "분할"이나 슈퍼/서브타입 "분리"는 반정규화가 아니라 정규화 방향이다.

### 관계형 모델의 특수 구조

| 구조 | 판단 기준 | 특징 |
| --- | --- | --- |
| 계층형 모델 | 엔터티가 자기 자신과 관계를 맺는가 | Self Join, 상위-하위 구조 표현 |
| 상호배타 모델 | 하나의 관계가 후보 엔터티 중 정확히 하나와만 대응되는가 | 중복이 원천적으로 없어 UNION = UNION ALL |

## 2. 판정용 결정 트리

```text
① 조인 필요성
필요한 정보가 한 테이블에 다 있는가?
├─ 예 → 단일 테이블 조회
└─ 아니오 → 관계·공통식별자 있는가? → 예 → JOIN(정보 통합이 목적)
```

```text
② 트랜잭션
여러 DML이 하나의 업무 단위인가?
├─ 아니오 → 개별 처리
└─ 예 → 모두 성공(COMMIT) / 하나라도 실패(ROLLBACK)
"반드시 함께 등록" 요구사항 → ERD 관계가 필수참여로 설정됐는가 확인
```

```text
③ 반정규화
성능 문제 확인 → 조인·집계 비용이 반복적으로 큰가 → 정합성 위험 감수 가능한가
→ 병합 / 분할(수직·수평) / 중복컬럼추가 / 중복관계추가(유일하게 무결성 위험 없음)
```

**사례형 문제 풀이 규칙:**

```text
사례형: "반드시 함께"·"성능이 느리다" 같은 표현이 트랜잭션(정합성) 문제인지 반정규화(성능) 문제인지부터 구분
→ 목적이 정합성이면 관계의 필수참여로 해결, 목적이 성능이면 반정규화로 해결
```

## 3. 유사 사례 비교

| 사례 | 결정적 사실 | 적용 개념 | 결론 |
| --- | --- | --- | --- |
| "중복을 허용해 성능을 높인다"를 조인의 목적으로 서술 | 목적이 반정규화와 뒤바뀜 | 조인 vs 반정규화 | 오답(조인의 목적 아님) |
| "반드시 함께 등록" 요구사항인데 ERD가 선택관계 | 필수 요구사항 미반영 | 트랜잭션과 관계 참여도 | 데이터 모델 오류 |
| 함수종속 고려한 테이블 분할 | 정규화 기법을 반정규화로 오인 | 정규화 vs 반정규화 기법 | 반정규화 기법 아님(정규화 방향) |
| 반정규화 기법 중 무결성 위험 없는 것 | 병합·컬럼추가는 위험 있음 | 반정규화 기법별 위험도 | 중복 관계 추가만 무결성 위험 없음 |
| 엔터티가 자기 자신과 관계 | Self Join 여부 | 계층형 모델 | 계층형 모델 |

## 4. 반복 오답

| 선지 표현 | O/X | 틀린 이유 | 올바르게 고치면 |
| --- | :-: | --- | --- |
| 조인의 목적은 중복을 허용해 조회 성능을 높이는 것이다 | X | 이는 반정규화의 목적(목적·수단 혼동, D11) | 조인의 목적은 여러 엔터티에서 데이터를 한 번에 가져오는 것이다 |
| 트랜잭션의 목적은 성능 향상이다 | X | 트랜잭션의 목적은 정합성 보장(정의 바꿔치기, D1) | 트랜잭션의 목적은 데이터 정합성(원자성) 보장이다 |
| 트랜잭션은 하나의 엔터티만 사용할 수 있다 | X | 여러 엔터티를 포함할 수 있음(범위 과장, D4) | 트랜잭션은 여러 엔터티를 포함할 수 있다 |
| 반정규화 기법으로 함수종속을 고려한 테이블 분할을 사용한다 | X | 이는 정규화 기법(목적·수단 혼동, D11) | 함수종속을 고려한 테이블 분할은 정규화 기법이다 |
| 반정규화를 적용하는 이유는 입력 속도 저하다 | X | 입력 속도 저하는 반정규화의 부작용이지 이유가 아님(방향 역전, D6) | 반정규화를 적용하는 이유는 조회 성능 향상이다 |
| 상호배타 모델에서는 UNION과 UNION ALL의 결과가 다르다 | X | 상호배타 모델은 중복이 없어 결과가 같음(반대 개념 적용, D2) | 상호배타 모델은 중복이 없으므로 UNION과 UNION ALL의 결과가 같다 |

## 5. 자가 점검

표와 결정 트리를 가린 상태에서 답한다. 정답만 쓰지 말고 판정 기준을 한 문장으로 함께 제시할 것.

1. (핵심개념설명형) 조인이 필요한 이유는 무엇이며, 조인의 목적을 "성능 향상"이라고 답하면 왜 틀린 것인가?
2. (핵심개념설명형) 트랜잭션의 목적은 무엇이며, "트랜잭션을 사용하면 성능이 좋아진다"는 서술이 왜 오답인가?
3. (유사개념구별형) 조인의 목적과 반정규화의 목적을 각각 한 문장으로 설명하고 무엇이 정반대인지 밝히시오.
4. (유사개념구별형) "함수종속을 고려한 테이블 분할"과 "반정규화의 테이블 분할(수직/수평)"은 왜 서로 다른 방향인가?
5. (사례판정형) "회원가입 시 반드시 휴대폰 번호를 등록해야 한다"는 요구사항이 있는데 ERD의 회원-회원연락처 관계가 선택참여(0..*)로 그려져 있다. 무엇이 문제인가?
6. (사례판정형) 배송 엔터티에 회원번호 컬럼을 추가해 조인 없이 배송 정보를 조회할 수 있게 했다. 이 조치의 이름과 감수해야 할 위험은 무엇인가?
7. (반복오답교정형) "반정규화를 적용하는 이유는 입력 속도 저하다"라는 문장의 어디가 틀렸는지 지적하고 올바른 문장으로 고치시오.
8. (결정트리재현형) 아래 반정규화 판정 트리의 빈칸을 채우시오.

```text
성능 문제가 확인됐는가?
├─ 아니오 → (        )
└─ 예 → 조인·집계 비용이 반복적으로 큰가?
   ├─ 아니오 → (        )
   └─ 예 → 정합성 위험을 감수할 수 있는가?
      ├─ 아니오 → (        )
      └─ 예 → 반정규화 기법 선택
         ├─ 테이블 병합
         ├─ 테이블 분할(수직/수평)
         ├─ 중복 컬럼 추가
         └─ (        ) ← 유일하게 무결성 위험 없는 기법
```

<details>
<summary>자가 점검 정답</summary>

1. 조인은 정규화로 여러 테이블에 나뉜 데이터를 다시 결합해 조회하기 위한 것이다 — 판정 기준: "정보를 한 번에 가져오는 것"이 목적이면 조인, "중복을 허용해 조회를 빠르게 하는 것"이 목적이면 반정규화이므로 둘을 바꿔 쓰면 안 된다.
2. 트랜잭션의 목적은 데이터 정합성(원자성) 보장이다 — 판정 기준: 트랜잭션은 논리적 업무 단위를 하나의 커밋으로 묶어 정합성을 지키는 장치이지, 조회·처리 속도를 높이는 장치가 아니다.
3. 조인은 "나뉜 데이터를 다시 합쳐 조회"하는 것이고 반정규화는 "애초에 합쳐서(중복 허용) 저장"하는 것이다 — 판정 기준: 조인은 데이터를 나눈 상태를 유지한 채 필요할 때만 결합하고, 반정규화는 미리 결합·중복시켜 저장한다는 점에서 방향이 반대다.
4. 함수종속을 고려한 분할은 이상현상을 없애기 위한 정규화 방향이고, 반정규화의 수직/수평 분할은 자주 쓰는 컬럼·로우만 따로 모아 조회 성능을 높이기 위한 것이다 — 판정 기준: 목적이 "무결성 확보"면 정규화 방향, "조회 성능 향상"이면 반정규화 방향이다.
5. "반드시"라는 필수 요구사항인데 관계가 선택참여로 설정돼 있어 휴대폰 번호 없이도 회원이 등록될 수 있다는 것이 문제다 — 판정 기준: 필수 트랜잭션 요구사항은 반드시 필수참여 관계로 반영되어야 한다.
6. 이는 반정규화 기법 중 "중복 컬럼 추가"이며, 배송 엔터티의 회원번호와 회원 엔터티의 실제 값이 어긋나는 정합성 위험을 감수해야 한다 — 판정 기준: 조인 감소라는 성능 이익과 중복 데이터의 정합성 위험을 항상 함께 따져야 한다.
7. 입력 속도 저하는 반정규화의 부작용이지 적용 "이유"가 아니다 — 올바른 문장: "반정규화를 적용하는 이유는 조회 성능 향상이다." 판정 기준: 선지가 이유와 부작용을 뒤바꿔 서술하는지 확인한다.
8. 빈칸 정답(위에서부터): 정규화 구조 유지 / 다른 성능 원인(인덱스 등) 검토 / 인덱스·쿼리 개선 우선(반정규화 보류) / 중복 관계 추가 — 판정 기준: 성능 문제 확인 → 비용 확인 → 위험 감수 가능 여부 순으로 내려가며, 위험이 없는 유일한 기법은 중복 관계 추가다.
