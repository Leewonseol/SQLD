# [PERF-01] 반정규화의 목적과 기법(병합/분할/추가), 성능 데이터 모델링

> [!IMPORTANT]
> **핵심 법리:**
> 반정규화(De-normalization)는 조회 성능을 향상시키기 위해 이미 정규화된 데이터모델에 의도적으로 중복을 허용하는 물리적 모델링 단계의 기법이며, 정규화와 목적·수단이 정반대다. 반정규화 기법은 테이블 병합, 테이블 분할(수직/수평), 중복 컬럼 추가, 중복 관계 추가로 나뉘며, 함수종속을 고려해 이상현상이 없도록 테이블을 "분할"하거나 슈퍼/서브타입을 "분리"하는 것은 오히려 정규화 방향이므로 반정규화 기법이 아니다.
>
> [!TIP]
> **정답을 가르는 사실:**
> "반정규화 기법이 아닌 것"을 고를 때 "함수종속을 고려한 분할", "슈퍼/서브타입 분리"가 나오면 이는 정규화 방향이므로 정답 후보다. "반정규화 적용 이유"를 물을 때 "입력/갱신 속도 저하"가 나오면 이는 반정규화의 부작용이지 이유가 아니므로 정답 후보다.
>
> [!WARNING]
> **반복 오답:**
> 정규화와 반정규화의 목적을 서로 바꿔치기(무결성 보장 ↔ 조회성능 향상), 반정규화 기법 목록에 정규화 기법(함수종속 분할, 슈퍼/서브타입 분리)을 섞어 넣기, 반정규화의 부작용(입력 속도 저하, 무결성 위험)을 반정규화를 "적용하는 이유"로 뒤집어 서술하기.

## 1. 판시사항

- 반정규화란 무엇이며, 정규화와 목적·수단이 어떻게 다른가?
- 반정규화의 구체적 기법(테이블 병합/분할, 컬럼 추가, 관계 추가)에는 어떤 것이 있으며, 무엇이 반정규화 기법이 아닌가?
- 반정규화를 적용하는 정당한 이유와 반정규화의 부작용은 어떻게 구별하는가?

## 2. 핵심 법리

> 반정규화는 정규화로 분리된 테이블을 다시 통합하거나 중복을 허용하여 조회(조인) 성능을 향상시키기 위해 물리적 모델링 단계에서 수행하는 기법이다. 정규화의 목적이 데이터 무결성 보장(이상현상 제거)이라면, 반정규화의 목적은 그 반대편 극단인 조회 성능 향상이며, 이 과정에서 데이터 무결성이 깨질 위험을 감수한다(다만 중복 관계 추가처럼 무결성 위험이 없는 기법도 있다). 반정규화의 대표 기법은 ① 테이블 병합(1:1 관계 테이블 통합, 슈퍼/서브타입 통합), ② 테이블 분할(수직분할=자주 쓰는 컬럼만 분리, 수평분할=자주 쓰는 로우만 분리), ③ 중복 컬럼 추가(다른 테이블의 값을 복제해 저장), ④ 중복 관계 추가(조인 경로를 단축하기 위해 관계선을 추가)이다. 반면 함수종속성을 고려해 이상현상이 없도록 테이블을 나누는 것이나 슈퍼/서브타입을 "분리"하는 것은 반정규화가 아니라 정규화 방향의 작업이다. 반정규화를 적용하는 정당한 이유는 "특정 범위의 데이터만 자주 처리되어 성능 저하가 명백히 예상될 때"이며, "입력 속도가 느려질 것을 막기 위해"는 반정규화를 적용하는 이유가 아니라 오히려 반정규화의 대표적인 부작용이다.

## 3. 법리 적용 분기

```text
선지/상황이 다루는 것은?
│
├─ "반정규화 기법인가?"를 판별
│  ├─ 테이블 병합(1:1 관계 통합, 슈퍼/서브타입 통합)
│  │  └─ 반정규화 기법(병합)
│  ├─ 중복 컬럼 추가(다른 테이블 값을 복제해 저장)
│  │  └─ 반정규화 기법(컬럼 추가)
│  ├─ 중복 관계 추가(조인 경로 단축용 관계선 추가) — 무결성 위험 없음
│  │  └─ 반정규화 기법(관계 추가)
│  ├─ 수직/수평 분할(자주 쓰는 컬럼·로우만 분리)
│  │  └─ 반정규화 기법(분할)
│  └─ 함수종속을 고려한 분할, 슈퍼/서브타입 "분리"
│     └─ 정규화 방향 — 반정규화 기법이 아님(오답 함정)
│
└─ "반정규화를 적용하는 이유인가?"를 판별
   ├─ "특정 범위 조회 시 성능이 확실히 향상되는 경우"
   │  └─ 정당한 이유
   └─ "입력/갱신 속도가 저하되는 것을 막기 위해"
      └─ 이유가 아님(반정규화의 부작용을 이유로 뒤바꾼 함정)
```

### 사실관계

"반정규화의 기법이 아닌 것은?"이라는 질문에 4개 선지가 제시되며, 그중 하나는 "슈퍼타입/서브타입 테이블을 분리한다"이다.

### 쟁점

슈퍼/서브타입 테이블을 "분리"하는 것이 반정규화 기법(병합 방향)인지, 아니면 반대 방향(정규화)의 작업인지가 쟁점이다.

### 적용 법리

반정규화는 조회 성능을 위해 테이블을 통합·중복시키는 기법이므로, 슈퍼/서브타입을 오히려 "병합"하는 것이 반정규화 기법이다. "분리"는 정규화 방향의 작업이므로 반정규화 기법이 아니다.

**정답: ④**

| 유선배모의1(page_50, 문제05) | 반정규화를 적용하는 이유로 가장 적절하지 않은 것을 고르는 문제 | 기법이 아니라 "적용 이유" 판별형 — "입력할 때 속도 저하가 예상되는 경우"를 틀린 이유로 제시(반정규화의 부작용이지 이유가 아님) | 반정규화의 목적(조회성능 향상)과 부작용(입력속도저하)을 구분하는 동일한 판단 규칙 |
| 이기적기출(page_13, 문제06) | 정규화로 직접 얻는 효과가 아닌 것을 고르는 문제(주 법리는 NORM-01) | "조회성능 향상"을 정규화의 효과로 서술한 함정(정규화는 오히려 조인 증가로 조회성능이 저하될 수 있음) | "정규화는 조회성능 향상을 목적으로 하지 않는다"는 사실이 반정규화가 별도로 필요한 이유를 뒷받침하므로, PERF-01의 보조 법리로도 인용 가능 |

## 8. 구별 판례

| 구별 요소 | 이 사건(PERF-01) | 비교 사건 | 답이 달라지는 이유 |
| --- | --- | --- | --- |
| 목적 | 조회 성능 향상을 위해 중복을 허용 | NORM-01(정규화의 목적)은 삽입·갱신·삭제 이상현상을 없애 데이터 무결성을 보장하기 위해 중복을 제거 | 두 법리는 "중복을 다루는 방향"이 정반대다 — 같은 소재(테이블 분할·병합)라도 목적이 성능이면 PERF-01, 무결성이면 NORM-01이 적용된다. 목적과 수단을 맞바꿔 서술하는 것이 이 둘을 헷갈리게 하는 가장 흔한 함정이다 |
| 수행 단계 | 물리적 모델링 단계에서 수행 | NORM-01은 논리적 모델링 단계에서 수행 | 동일한 "테이블을 나눈다/합친다"는 행위도 어느 단계·목적에서 이뤄지는지에 따라 법리가 갈린다 |
| 다루는 대상 | 성능을 위한 물리설계 기법(반정규화) | MOD-01의 데이터 모델링 유의사항(중복/비유연성/비일관성)은 모델링 자체의 구조적 결함 | MOD-01의 "중복"은 지양해야 할 결함이지만, PERF-01의 "중복 허용"은 성능을 위해 의도적으로 선택하는 기법이다. 같은 "중복"이라는 단어가 문맥에 따라 결함(MOD-01)과 전략(PERF-01)으로 반대 취급된다 |

## 9. 출제자가 바꾸는 사실

- 정규화 기법(함수종속 분할, 슈퍼/서브타입 분리)을 반정규화 기법 목록에 끼워넣기
- 반정규화의 부작용(입력속도저하, 무결성위험)을 도입 이유로 뒤바꾸기
- 정규화·반정규화의 목적(무결성 vs 성능)을 맞바꾸기
- 성능 데이터 모델링의 전체 수행 순서를 뒤섞기
- 무결성 위험이 없는 기법(중복 관계 추가)을 위험이 있는 기법인 것처럼 서술

## 10. 시험용 한 줄 법리

> 정규화는 무결성을 위해 나누고, 반정규화는 성능을 위해 합친다 — 분리·분할이 목적이면 정규화, 병합·중복추가가 목적이면 반정규화다.
