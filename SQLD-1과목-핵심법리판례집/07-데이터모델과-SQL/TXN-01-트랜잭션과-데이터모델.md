# [TXN-01] 트랜잭션과 데이터 모델

> [!IMPORTANT]
> **핵심 법리:**
> 트랜잭션은 업무상 나눌 수 없는 하나의 논리적 작업 단위로서 원자성(모두 성공 또는 모두 실패)을 가지며, 하나의 커밋 단위로 묶인다. 트랜잭션의 목적은 성능 향상이 아니라 데이터 정합성 보장이며, 하나의 트랜잭션 안에는 여러 엔터티가 함께 포함될 수 있다. "반드시 함께 등록되어야 한다"는 트랜잭션 요구사항은 논리적 모델링 단계에서 엔터티 간 관계의 필수참여로 반영해야 한다.
>
> [!TIP]
> **정답을 가르는 사실:**
> "트랜잭션의 목적"을 성능 향상/조회속도 개선으로 서술하면 오답이다. "반드시 함께 등록/생성"이라는 요구사항이 있는데 ERD의 관계가 선택참여(0..*)로 그려져 있으면, 그 요구사항이 데이터 모델에 반영되지 않은 것이다.
>
> [!WARNING]
> **반복 오답:**
> 트랜잭션의 목적을 성능 향상으로 서술하는 함정, 트랜잭션이 하나의 엔터티만 사용한다고 범위를 축소하는 함정, 필수 트랜잭션 요구사항을 선택관계 ERD로 설정해 놓고 문제없다고 서술하는 함정(필수↔선택 교환), 트랜잭션 반영을 물리설계 단계의 성능튜닝과 혼동하는 함정.

## 1. 판시사항

- 트랜잭션이란 무엇이며, 어떤 특성(원자성, 커밋 단위)을 가지는가?
- 트랜잭션 요구사항이 데이터 모델의 관계(필수/선택 참여)에 올바르게 반영되었는지는 어떻게 판별하는가?

## 2. 핵심 법리

> 트랜잭션은 업무상 하나로 취급해야 하는 논리적 작업 단위이며, 그 안의 모든 작업은 하나의 커밋 단위로 묶여 원자성(모두 성공하거나 모두 실패)을 보장해야 한다. 트랜잭션은 하나의 엔터티에 국한되지 않고 여러 엔터티(테이블)에 걸쳐 발생할 수 있으며, 트랜잭션의 목적은 성능 향상이 아니라 업무 데이터의 정합성을 지키는 것이다. 논리적 모델링 단계에서는 이러한 트랜잭션 요구사항(예: "A를 등록할 때 B도 반드시 함께 등록되어야 한다")을 엔터티 간 관계의 필수참여로 표현해야 하며, 요구사항이 필수임에도 관계가 선택참여로 설정되면 해당 요구사항이 데이터 모델에 반영되지 않아 정합성이 깨질 수 있다.

## 3. 법리 적용 분기

```text
선지/상황이 다루는 것은?
│
├─ "트랜잭션의 목적/효과"를 묻는 경우
│  ├─ "성능이 향상된다 / 성능튜닝을 할 수 있다"
│  │  └─ 틀림 — 트랜잭션의 목적은 논리적 작업단위(정합성) 보장,
│  │             성능튜닝은 물리설계 단계의 영역
│  └─ "모두 성공하거나 모두 실패해야 한다(원자성)", "하나의 커밋단위로 묶인다"
│     └─ 맞음
│
├─ "트랜잭션이 사용할 수 있는 엔터티 개수"
│  └─ "하나의 엔터티만 사용할 수 있다" → 틀림(여러 엔터티에 걸쳐 발생 가능)
│
└─ "반드시 함께 등록되어야 한다"는 요구사항이 있는 ERD인가?
   ├─ 해당 관계가 필수참여(1)로 설정됨 → 요구사항이 올바르게 반영됨
   └─ 해당 관계가 선택참여(0)로 설정됨 → 요구사항이 반영되지 않음(오류)
```

## 4. 이 문제들이 유사한 이유

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 트랜잭션의 정의(논리적 작업단위, 원자성, 커밋단위)와, 트랜잭션 요구사항을 관계의 필수·선택 참여로 반영하는 동일한 판단 규칙 |
| 공통 결정 사실 | 선지·ERD에 "성능향상"이 트랜잭션의 목적으로 등장하는지, "하나의 엔터티만" 사용 가능하다는 제한이 있는지, 필수 요구사항인데 관계가 선택으로 그려져 있는지 |
| 반복되는 오답 구조 | 트랜잭션 목적을 성능향상으로 뒤바꿈(D1 정의 바꿔치기), 트랜잭션이 다룰 수 있는 엔터티 범위를 하나로 축소(D3 조건 누락), 필수·선택 참여를 뒤바꿔 요구사항 미반영을 유도(D2 반대개념 적용) |
| 정답이 달라지는 조건 | ERD의 관계가 필수참여인지 선택참여인지, 그리고 그것이 실제 업무 요구사항(반드시 함께 등록)과 일치하는지 |

## 5. 대표 판례

### 사건 TXN-01-01

- 출처: 이기적 단원별 기출문제, SECTION03 모델이 표현하는 트랜잭션의 이해
- PDF 페이지: page_20 (교재 p.107)
- 원문 문제번호: 09
- 핵심 법리 ID: TXN-01
- 보조 법리 ID: REL-01

### 사실관계

회원과 회원연락처가 선택관계로 연결된 ERD가 제시되고, 업무 요구사항은 "회원가입 시 반드시 휴대폰 번호를 등록해야 한다"이다. 이 ERD가 트랜잭션 요구사항을 반영하는 데 있어 어떤 문제점을 가지는지 묻는다.

### 쟁점

"반드시 등록"이라는 필수 요구사항이 ERD 상에서 선택관계(회원연락처 없이도 회원 인스턴스 생성 가능)로 설정되어 있어, 요구사항과 데이터 모델이 불일치하는지가 쟁점이다.

### 적용 법리

트랜잭션 요구사항이 "필수"라면 논리적 모델링 단계에서 해당 관계를 필수참여로 표현해야 한다. 관계가 선택참여로 설정되어 있으면 휴대폰 번호 없이도 회원이 등록될 수 있으므로, "반드시 등록해야 한다"는 요구사항이 데이터 모델에서 보장되지 않는다.

### 주문

**정답: ③**

### 판결이유

```text
문제의 결정적 사실: 요구사항은 "반드시" 휴대폰 등록인데, ERD의 회원-회원연락처 관계가 선택(0..*)으로 설정됨
→ 적용되는 핵심 법리: 필수 트랜잭션 요구사항은 관계를 필수참여로 표현해야 데이터 모델에 반영된다
→ 정답 선지: ③(관계가 선택이라서 필수등록이 보장되지 않는다는 문제점)
```

## 9. 출제자가 바꾸는 사실

- 트랜잭션의 목적을 성능 향상으로 서술
- 트랜잭션이 "하나의 엔터티만" 사용한다고 범위를 축소
- 필수 요구사항의 관계를 선택참여로 설정해 놓고 문제없다고 서술(필수↔선택 교환)

## 10. 시험용 한 줄 법리
