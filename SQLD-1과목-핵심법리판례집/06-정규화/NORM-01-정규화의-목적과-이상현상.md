# [NORM-01] 정규화의 목적과 이상현상(삽입·갱신·삭제)

> [!IMPORTANT]
> **핵심 법리:**
> 정규화는 논리적 데이터 모델링 단계에서 함수종속성을 분석해 테이블을 무손실 분해하는 작업으로, 그 직접적 목적은 데이터 무결성 확보와 삽입·갱신·삭제 세 가지 이상현상의 제거다.
>
> [!TIP]
> **정답을 가르는 사실:**
> 이상현상 사례가 "정보가 없어서 못 넣는다"인지, "일부만 고쳐서 어긋난다"인지, "지우니 필요한 다른 정보까지 같이 없어진다"인지로 삽입·갱신·삭제이상을 구분한다.
>
> [!WARNING]
> **반복 오답:**
> 존재하지 않는 "생성이상"이라는 용어를 이상현상 목록에 끼워넣는 함정, 정규화를 물리적 모델링 단계의 작업으로 서술하는 함정(D5), 정규화의 효과를 "조회성능향상"으로 과장하는 함정(D11, 실제로는 반정규화의 목적).

## 1. 판시사항

- 정규화는 어느 모델링 단계에서, 무엇을 위해 수행하는가?
- 삽입이상·갱신이상·삭제이상은 각각 어떤 상황에서 발생하며, 서로 어떻게 구별되는가?
- 정규화로 "직접" 얻는 효과가 아닌 것(예: 조회성능향상)을 어떻게 가려내는가?

## 2. 핵심 법리

> 정규화(Normalization)는 함수종속성 분석을 근거로 하나의 테이블에 여러 종속관계가 뒤섞여 있을 때 이를 여러 테이블로 무손실 분해하는 논리적 모델링 단계의 작업이다. 정규화를 하지 않으면 한 테이블 안에 서로 다른 주제의 데이터가 뒤섞여 (1) 삽입이상 — 삽입하려는 대상과 무관한 다른 정보가 없어서 원하는 데이터를 아예 넣지 못하는 현상, (2) 갱신이상 — 같은 값이 여러 행에 중복 저장되어 있어 일부만 고치면 데이터 간 불일치가 생기는 현상, (3) 삭제이상 — 특정 행을 지우면 함께 저장돼 있던 다른 필요한 정보까지 같이 사라지는 현상이 발생한다. 정규화의 직접적 목적은 이 세 이상현상의 제거와 데이터 무결성 확보이며, 조회 성능 향상은 정규화가 아니라 반정규화의 목적이다.

## 3. 법리 적용 분기

```text
정규화/이상현상 문제인가?
│
├─ "정규화는 어느 단계에서 하는가" 묻는 경우
│  └─ 논리적 모델링 단계(물리적 모델링 아님, D5 주의)
│
├─ 특정 이상현상 사례가 제시된 경우
│  ├─ 필요한 다른 정보가 없어 입력 자체가 불가능 → 삽입이상
│  ├─ 중복 저장된 값 중 일부만 변경되어 불일치 발생 → 갱신이상
│  └─ 행 삭제 시 함께 필요한 다른 정보까지 소실 → 삭제이상
│
└─ "정규화로 직접 얻는 효과"를 묻는 경우
   └─ 무결성 확보/중복 제거는 O, 조회성능향상은 X(D11, 반정규화의 목적)
```

| 기준 | 내용 |
| --- | --- |
| 공통 핵심 법리 | 이상현상 3유형(삽입/갱신/삭제)의 정의와, 정규화의 목적·수행 단계를 구분하는 동일한 판단 규칙 |
| 공통 결정 사실 | 지문에서 "정보가 없어서 못 넣는다"/"일부만 바뀌어 어긋난다"/"지우니 같이 없어진다" 중 어떤 서술인지, 그리고 "정규화=논리단계, 목적=무결성"이라는 명제가 참인지 |
| 반복되는 오답 구조 | 존재하지 않는 "생성이상" 용어 끼워넣기, 정규화 수행단계를 물리모델링으로 서술(D5), 정규화 효과를 조회성능향상으로 과장(D11) |
| 정답이 달라지는 조건 | 제시된 상황이 "정보 없어서 못 넣음"인지 "일부만 고쳐 불일치"인지 "지우니 같이 사라짐"인지에 따라 세 이상현상이 갈린다 |

### 사실관계

"삽입이상(Insert Anomaly)의 예로 가장 적절한 것은?"이라는 질문에 4개 선지가 제시된다. 그중 하나는 "학생을 입력하려 했으나 담당 교수 정보가 없어 입력할 수 없었다"는 상황이고, 다른 선지들은 각각 갱신이상·삭제이상에 해당하는 사례로 구성되어 있다.

### 쟁점

같은 테이블에 서로 다른 두 주제(학생 정보, 교수 정보)가 뒤섞여 있을 때, "정보가 없어서 입력 자체가 불가능한 상황"이 삽입·갱신·삭제이상 중 어느 것에 해당하는지 구별하는 것이 핵심이다.

### 적용 법리

필요한 정보(교수 정보)가 아직 없어서 상관없는 다른 정보(학생 정보)조차 입력할 수 없는 상황은 삽입이상의 전형적 정의에 해당한다. 이미 저장된 값 중 일부만 고쳐서 불일치가 생기는 것은 갱신이상, 행을 지울 때 다른 정보까지 같이 사라지는 것은 삭제이상이므로 이 사례와는 다르다.

### 주문

**정답: ②**

### 판결이유

```text
문제의 결정적 사실: "교수 정보가 없어서 학생 정보조차 입력할 수 없다"
→ 적용되는 핵심 법리: 필요한 다른 정보의 부재로 삽입 자체가 불가능한 것은 삽입이상의 정의
→ 정답 선지: ②(삽입이상의 사례)
```

## 9. 출제자가 바꾸는 사실

- 삽입/갱신/삭제이상 사례를 서로 바꿔서 제시
- 존재하지 않는 "생성이상"이라는 용어를 이상현상 목록에 끼워넣기
- 정규화 수행 단계를 물리적 모델링으로 서술(D5)
- 정규화의 효과를 조회성능향상처럼 과장(D11, 실제로는 반정규화의 목적)

## 10. 시험용 한 줄 법리
