인쇄 권장: A4 · 배율 100% · 머리글/바닥글 끄기

실제 SQLD보다 어렵게 — 조건·방향·분류축·예외를 중첩한 문제

난도는 문장 길이가 아니라 개념 경계에서 나오게 설계했습니다. 논리학 명칭이나 관계 유형의 영문 라벨(type of 등)을 몰라도, SQLD 개념만 정확히 알면 선지의 한국어 설명만으로 풀립니다. 오답 코드(D1~D12)는 해설에서 확인하세요. 태그: 기본 정의·분류 직접 판정 · 적용 그림·사례 적용 · 모래주머니 개념 결합형.

기준 지문: 「SQLD 1과목 협업형 지문」. 지문에서 익힌 협업 흐름을 기본으로 하되, 세부 분류·ERD·정규화 조건은 각 문항의 보기에서 보충한다.

① 총론·협업·모델링 단계 (8문항)

문항 1기본

데이터 모델링을 "협업 언어"라고 부르는 이유로 가장 적절한 것은?

  1. ①현업 담당자가 요구사항을 문서로 작성하는 절차이기 때문이다.
  2. ②현업 담당자·모델러·개발자·DBA가 같은 업무를 서로 다른 관심사로 바라보는 간극을, 단순화·추상화·명확화를 통해 같은 의미로 좁혀 주기 때문이다.
  3. ③개발자가 SQL을 작성하기 위한 사전 준비 단계이기 때문이다.
  4. ④DBA가 백업·복구 정책을 수립하는 근거 문서이기 때문이다.
  5. ⑤모든 이해관계자가 동일한 도구를 사용해야 한다는 규정이기 때문이다.
문항 2기본

온라인 쇼핑몰이 고객 배송지를 주문·반품·상담 기능에 각각 저장한 뒤 주소 형식을 바꾸려 한다. 이 사례와 데이터 모델링의 중요성을 연결한 설명으로 옳지 않은 것은?

  1. ①같은 배송지를 여러 곳에 저장한 것은 중복 위험을 만든다.
  2. ②주소 형식을 바꿀 때 여러 프로그램과 구조를 함께 고쳐야 한다면 비유연성이 드러난다.
  3. ③일부 화면만 새 주소로 바뀌어 화면마다 값이 달라지면 비일관성이 발생한다.
  4. ④ERD를 한 번 작성했다는 사실만으로 위 세 문제가 자동으로 사라진다.
  5. ⑤모델링은 요구사항을 그림으로 공유하여 관계자 사이의 해석 차이와 변경의 파급효과를 줄이는 데 도움을 준다.
문항 3기본

모델링 단계별로 논의의 중심이 되는 협업 주체를 짝지은 것으로 가장 적절한 것은? 실제 프로젝트에서는 역할이 겹칠 수 있다.

  1. ①개념적 모델링 — 개발자와 DBA
  2. ②논리적 모델링 — 모델러와 개발자가 엔터티·속성·관계·제약을 구체화한다.
  3. ③물리적 모델링 — 현업 담당자와 모델러
  4. ④세 단계 모두 DBA가 단독으로 수행한다.
  5. ⑤협업 주체는 어느 단계에서나 완전히 같으며, 단계별로 논의의 중심이 달라지지 않는다.
문항 4적용

한 프로젝트에서 "회원 등급 체계를 어떻게 관리할지 아직 DBMS도 정해지지 않은 상태에서, 현업 담당자와 모델러가 회의를 통해 '회원'과 '주문'을 핵심 관리 대상으로 합의했다." 이 활동이 속하는 단계로 옳은 것은?

  1. ①물리적 모델링 — 이미 테이블과 컬럼이 정해졌기 때문이다.
  2. ②개념적 모델링 — DBMS를 정하지 않은 채 업무 중심으로 핵심 대상을 합의하는 단계의 특징과 일치한다.
  3. ③논리적 모델링 — 정규화가 이미 수행되었기 때문이다.
  4. ④ANSI/SPARC의 개념 스키마 단계이므로 모델링 3단계와 같은 것으로 본다.
  5. ⑤이 정보만으로는 단계를 특정할 수 없다.
문항 5적용

ANSI/SPARC 3단계 구조는 하나의 데이터베이스를 사용자별 화면인 외부 스키마, 조직 전체의 통합 논리 구조인 개념 스키마, 실제 저장 방식인 내부 스키마로 나누어 본다. 영업팀 화면에는 고객명·연락처만 보이고 정산팀 화면에는 고객명·결제이력만 보이지만, 두 화면의 데이터가 하나의 통합 논리 구조에서 나온다면 옳은 설명은?

  1. ①영업팀·정산팀 화면은 각각 서로 다른 개념 스키마이며, 데이터베이스 하나에는 개념 스키마가 여러 개 존재해야 한다.
  2. ②영업팀·정산팀 화면은 외부 스키마이고, 그 바탕이 되는 통합된 논리 구조는 개념 스키마다. 개념 스키마는 하나의 데이터베이스에 하나만 존재한다.
  3. ③이 상황은 물리적 독립성이 아니라 데이터 모델링 3단계 중 물리적 모델링에 해당한다.
  4. ④두 화면이 다르다는 사실 자체가 내부 스키마가 서로 다르다는 뜻이다.
  5. ⑤외부 스키마가 여러 개 존재하는 것은 비정상적인 설계다.
문항 6모래주머니

다음 두 진술을 검토하시오.
(A) "개념 스키마"라는 용어와 "개념적 모델링"이라는 용어는 둘 다 '개념'이라는 말이 들어 있으므로 같은 대상을 가리킨다.
(B) 데이터 모델링 3단계와 ANSI/SPARC 3단계 스키마는 둘 다 '3단계'로 이루어져 있으므로 서로 대응하는 개념이다.

  1. ①(A), (B) 모두 옳다.
  2. ②(A)만 옳다. 이름이 같으면 분류축도 같기 때문이다.
  3. ③(A), (B) 모두 틀렸다. 개념적·논리적·물리적 모델링은 설계가 구체화되는 과정을 나눈 것이고, ANSI/SPARC의 외부·개념·내부 스키마는 완성된 데이터베이스를 보는 층위를 나눈 것이다. 이름이나 단계 수가 같다는 이유로 같은 분류가 되지는 않는다.
  4. ④(B)만 옳다. 3단계라는 숫자가 같으므로 논리적으로 대응된다.
  5. ⑤(A), (B)는 처음엔 다른 개념이었지만 실무에서는 항상 같은 뜻으로 쓰인다.
문항 7모래주머니

"물리적 독립성이 확보된 시스템이라면, 논리적 독립성도 당연히 함께 확보되어 있을 것이다. 왜냐하면 두 독립성 모두 '변경의 영향을 최소화한다'는 같은 목표를 가지고 있기 때문이다." 이 추론에 대한 판단으로 옳은 것은?

  1. ①타당하다. 목표가 같으면 하나가 확보될 때 다른 하나도 자동으로 확보된다.
  2. ②부당하다. 물리적 독립성은 내부 스키마 변경이 개념·외부 스키마에 주는 영향을, 논리적 독립성은 개념 스키마 변경이 외부 스키마에 주는 영향을 다루는 서로 다른 계층의 문제이므로, 같은 "목표"를 공유한다는 사실만으로 한쪽이 다른 쪽을 함의하지 않는다.
  3. ③부당하다. 애초에 두 독립성은 서로 반대 방향으로 작동하므로 동시에 성립할 수 없다.
  4. ④타당하다. 물리적 독립성이 논리적 독립성의 필요조건이기 때문이다.
  5. ⑤판단할 수 없다. 독립성은 정량적으로 측정할 수 없는 개념이기 때문이다.
문항 8모래주머니

한 팀이 다음과 같이 주장한다. "우리는 이번 프로젝트에서 ERD를 그리고 정규화까지 마쳤다. 데이터 모델링을 거쳤으므로, 우리 시스템은 중복·비유연성·비일관성 문제로부터 안전하다." 이 주장에 대한 가장 정확한 비판은?

  1. ①ERD를 그렸다는 사실 자체가 이미 품질을 보장하므로 이 주장은 옳다.
  2. ②모델링의 세 가지 효과(파급효과 감소·요구사항의 간결한 표현·품질 확보)는 모델링을 "잘" 수행했을 때 기대되는 결과이지, ERD 작성이나 정규화라는 절차를 거쳤다는 사실 자체가 자동으로 보장하는 것이 아니다. 부실하게 이루어진 모델링은 오히려 품질 저하로 이어질 수도 있다.
  3. ③정규화만 마치면 비유연성 문제는 원천적으로 발생할 수 없다.
  4. ④ERD는 개념적 모델링 산출물이 아니므로 이 주장과 무관하다.
  5. ⑤중복·비유연성·비일관성은 물리적 모델링 단계에서만 발생하는 문제이므로 논리 모델 단계의 정규화와는 관련이 없다.

② 엔터티·속성·도메인 (10문항)

문항 9기본

업무 대상을 엔터티로 판단하는 기준에 대한 설명으로 가장 적절한 것은?

  1. ①요구사항에 명사로 등장하면 독립 관리 여부를 검토하지 않아도 곧바로 엔터티가 된다.
  2. ②독립적으로 관리할 필요가 있는지, 복수의 인스턴스와 의미 있는 속성이 있는지, 각 인스턴스를 식별할 수 있는지를 우선 검토한다. 다른 엔터티와의 관계도 일반적인 판단 기준이지만 코드성·통계성 엔터티에는 예외가 있을 수 있으며, 최종 구조는 관계자들이 검토해 합의한다.
  3. ③다른 엔터티와 직접 연결된 관계선이 없으면 예외 없이 엔터티가 될 수 없다.
  4. ④엔터티 여부는 업무 기준과 무관하게 이해관계자의 선호만으로 결정한다.
  5. ⑤속성이 없어도 이름만 붙일 수 있으면 엔터티가 된다.

  2. ②도메인은 속성이 가질 수 있는 값의 범위(자료형·길이·형식·허용범위)를 규정한다.

  4. ④하나의 속성에는 도메인을 둘 이상 지정해야 한다.
  5. ⑤도메인은 엔터티 간 관계의 필수·선택 참여 여부를 결정한다.

  2. ②틀렸다. 조인은 정규화로 나뉜 데이터를 필요할 때 모아서 "조회하는 방법"이고, 반정규화는 애초에 나뉜 구조 자체를 미리 합쳐 두어 조인이 덜 필요하게 만드는 "설계 방법"이다. 둘 다 조회와 관련은 있지만 작동 층위와 수단이 다르므로 같은 기법으로 볼 수 없다.
  3. ③틀렸다. 조인은 물리적 모델링에서만, 반정규화는 논리적 모델링에서만 쓰이기 때문이다.
  4. ④옳다. 반정규화가 곧 조인 자체를 가리키는 다른 이름이기 때문이다.
  5. ⑤조인과 반정규화는 서로 반대 개념이므로 동시에 쓰일 수 없다.

한 시스템에서 "사원" 엔터티가 자기 자신을 참조해 관리자-부하 관계를 표현하고 있었는데, 개발팀이 조회 성능을 위해 "사원" 테이블에 "최상위관리자명"이라는 컬럼을 추가로 저장하기로 했다(원래는 재귀 관계를 반복 조회해야 알 수 있던 값). 이 결정에 대한 설명으로 옳은 것은?

  1. ①이는 셀프 조인 구조 자체를 없애는 정규화 작업이다.
  2. ②이는 반복 조회로 얻던 값을 미리 계산해 중복 컬럼으로 저장해 두는 반정규화의 한 형태이며, 목적은 조회 성능 향상이다. 다만 조직 개편으로 상위 관계가 바뀌면 이 컬럼도 함께 갱신해야 하는 위험이 따른다.
  3. ③셀프 조인 구조에는 이런 방식의 반정규화를 적용할 수 없다.
  4. ④이 컬럼을 추가해도 원본 재귀 관계와 무관하므로 값이 어긋날 위험은 전혀 없다.
  5. ⑤이 작업은 참조무결성 제약과 아무 관련이 없다.
