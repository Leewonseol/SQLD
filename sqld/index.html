SQLD 개념 관계망

SQLD 1과목(데이터 모델링의 이해)과 2과목(SQL 기본·활용·관리)의 개념과 문제를 다섯 가지 관계로만 연결한 지도입니다. 세 지도는 같은 화면 구성과 탐색 기능을 공유하지만 각각 독립적으로 열 수 있습니다.

A · 1과목 전용

데이터 모델링의 이해

모델링 특징·단계, ERD, 스키마와 독립성, 엔터티·속성·도메인, 관계, 식별자·키·무결성, 함수적 종속·정규화, 반정규화, 특수 관계, 트랜잭션·NULL.

 B · 1·2과목 대응

설계 원리 ↔ SQL 구현·처리

식별자·무결성 ↔ PRIMARY KEY·FOREIGN KEY, 도메인 ↔ 자료형·CHECK, 정규화 ↔ DDL·DML·JOIN, ACID ↔ TCL, NULL ↔ IS NULL·집계, 계층 관계 ↔ SELF JOIN·계층형 질의.

 C · 2과목 전용

SQL 기본·활용·관리

SELECT와 해석 순서, 함수·자료형, NULL·CASE, GROUP BY·HAVING·ORDER BY, JOIN·서브쿼리·집합, 확장 그룹, 윈도우·TOP-N, 계층형 질의·PIVOT, DML·TCL·DDL·DCL.

다섯 관계

관계 · 선 모양의미방향예
Type of하위 개념 집합이 상위 개념 집합에 포함된다하위 → 상위후보키 → 슈퍼키 (후보키는 슈퍼키의 일종)
Instance of개별 사례가 특정 개념·유형에 속한다사례 → 개념‘학번 + 주민등록번호’ → 슈퍼키
Part of구성 요소가 전체를 이룬다구성 요소 → 전체WHERE절 → SELECT문 (WHERE는 SELECT의 종류가 아니라 구성 절)
Cause of원인·개입이 문제·결과를 발생시키거나 발생 가능성에 영향을 준다원인 → 결과불필요한 중복 저장 → 갱신 이상
Data → Claim관찰 자료·검증 결과가 주장을 뒷받침한다자료 → 주장교수명 변경 후 조회 결과 → ‘불일치가 남지 않음’ (검증 예정)

다섯 관계로 정확하게 나타낼 수 없는 내용(단계의 순서, 대응, 분해, ‘관점에서 활용하는 도구’ 등)은 간선을 만들지 않고 노드 설명이나 대응표에 적었습니다.

문제해결도식: 두 인과 경로를 나란히

개입원인 ↕ 원인 변화문제 ↕ 기대효과
① 문제 발생 경로
원인불필요한 중복 저장
Cause of
문제갱신 이상 위험 증가
② 문제 해결 경로
개입함수적 종속 분석 후 정규화 적용
Cause of
원인 변화불필요한 중복 감소
Cause of
기대효과갱신 이상 위험 감소

문제와 해결책을 잇는 여섯 번째 간선은 없습니다. 두 경로 모두 Cause of만 쓰며, 원인을 제거해도 문제가 완전히 사라진다고 단정하지 않습니다. 각 인과 간선에는 결정적·충분조건·필요조건·확률적 중 어떤 성격인지 표시했습니다. 함수적 종속은 이 경로의 원인이 아니라 분해 기준이므로 Cause of로 연결하지 않습니다.

정확성 규칙 (데이터 검증기로 자동 검사)

  • WHERE는 SELECT문의 종류가 아니라 질의를 구성하는 절이다 → WHERE절 Part of SELECT문.
  • 후보키는 슈퍼키의 일종이다 → 후보키 Type of 슈퍼키.
  • 함수적 종속은 값 사이의 결정 관계다 → 함수적 종속 관련 노드에는 Cause of 간선이 없다.
  • 정규화는 갱신 이상의 종류가 아니다 → 정규화에서 이상 현상으로 가는 Type of가 없다.
  • DISTINCT는 원본 테이블의 저장 중복을 제거하지 않는다 → DISTINCT에서 저장 중복 감소로 가는 인과 경로가 없다.
  • JOIN은 참조 무결성 위반을 자동으로 해결하지 않는다 → JOIN만 적용한 개입에서 무결성 개선으로 가는 인과 경로가 없다.
  • 검증하지 않은 기대효과를 관측 결과처럼 표시하지 않는다 → 모든 Data → Claim은 ‘검증 예정’ 또는 ‘예시’.
