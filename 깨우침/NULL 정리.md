# NULL 정리

## 1. 한 줄 정의

| 항목 | 내용                                                                                |
| -- | --------------------------------------------------------------------------------- |
| 정의 | `NULL`은 값이 알려지지 않았거나, 존재하지 않거나, 적용되지 않음을 나타내는 특별한 표지다.                            |
| 특징 | 일반 값과 달리 비교·연산·집계·조인·그룹화·정렬에서 별도 규칙이 적용된다.                                        |
| 주의 | `NULL`은 숫자 `0`, 빈 문자열, 공백 문자와 동일한 값이 아니다. 다만 Oracle에서는 빈 문자열 `''`을 `NULL`처럼 취급한다. |

기존 자료의 기본 정의와 비교·연산·집계·정렬에 별도 규칙이 적용된다는 방향은 적절하다. 

---

## 2. NULL 판단 순서

| 순서 | 확인 질문                                      | 적용 규칙                      |
| -: | ------------------------------------------ | -------------------------- |
|  1 | `NULL`이 어디에 등장하는가?                         | 비교·산술·집계·조인·그룹화·정렬 중 위치 확인 |
|  2 | 해당 연산이 `NULL`을 전파하는가?                      | 산술 연산은 일반적으로 결과가 `NULL`    |
|  3 | 해당 연산이 `NULL`을 제외하는가?                      | 주요 집계 함수는 `NULL` 제외        |
|  4 | 행 자체를 세는가, 열 값을 세는가?                       | `COUNT(*)`와 `COUNT(열)` 구분  |
|  5 | 조건의 결과가 `TRUE`, `FALSE`, `UNKNOWN` 중 무엇인가? | `WHERE`는 `TRUE`만 통과        |
|  6 | DBMS별 차이가 있는가?                             | 정렬·빈 문자열·함수 차이 확인          |

기존 자료의 “위치 식별 → 포함·제외 판단 → 안쪽부터 계산 → DBMS 차이 확인” 순서는 유지해도 된다. 

---

# 비교와 조건

## 3. NULL 비교 규칙

| 표현                | 결과 또는 의미                  | 사용 여부                  |
| ----------------- | ------------------------- | ---------------------- |
| `COL = NULL`      | `UNKNOWN`                 | 사용하지 않음                |
| `COL <> NULL`     | `UNKNOWN`                 | 사용하지 않음                |
| `COL != NULL`     | `UNKNOWN`                 | 사용하지 않음                |
| `COL IS NULL`     | `COL`이 `NULL`이면 `TRUE`    | 사용                     |
| `COL IS NOT NULL` | `COL`이 `NULL`이 아니면 `TRUE` | 사용                     |
| `NULL = NULL`     | `UNKNOWN`                 | 두 NULL을 같은 값으로 비교하지 못함 |

기존 자료의 “일반 비교 연산자로 NULL을 비교할 수 없다”는 표현은 다음처럼 바꾸는 편이 정확하다.

> 일반 비교 연산자에 `NULL`이 포함되면 결과는 `TRUE`나 `FALSE`가 아니라 `UNKNOWN`이 된다. 

---

## 4. WHERE의 3값 논리

| 조건 결과     | WHERE 통과 여부 |
| --------- | :---------: |
| `TRUE`    |      통과     |
| `FALSE`   |      제외     |
| `UNKNOWN` |      제외     |

예시:

| 표현               | 논리 결과     | WHERE 결과 |
| ---------------- | --------- | -------- |
| `10 = 10`        | `TRUE`    | 행 유지     |
| `10 = 20`        | `FALSE`   | 행 제외     |
| `10 = NULL`      | `UNKNOWN` | 행 제외     |
| `NULL LIKE 'A%'` | `UNKNOWN` | 행 제외     |

---

## 5. IN과 NULL

| 조건                     | 결과        |
| ---------------------- | --------- |
| 일치값이 목록에 있음            | `TRUE`    |
| 일치값이 없고 `NULL`도 없음     | `FALSE`   |
| 일치값이 없고 목록에 `NULL`이 있음 | `UNKNOWN` |

예시:

| 표현               | 결과        |
| ---------------- | --------- |
| `1 IN (1, NULL)` | `TRUE`    |
| `2 IN (1, 3)`    | `FALSE`   |
| `2 IN (1, NULL)` | `UNKNOWN` |

따라서 기존의 다음 문장은 수정해야 한다.

| 기존 표현                     | 수정 표현                                                   |
| ------------------------- | ------------------------------------------------------- |
| `IN`은 NULL이 목록에 있어도 영향 없음 | 일치값이 있으면 `TRUE`지만, 일치값이 없고 목록에 `NULL`이 있으면 `UNKNOWN`이다. |

기존 자료의 `IN`과 `NOT IN` 비교는 이 부분을 보완해야 한다. 

---

## 6. NOT IN과 NULL

`NOT IN`은 여러 개의 `<>` 조건을 `AND`로 연결한 것과 유사하다.

```sql
COL NOT IN (1, 2, NULL)
```

개념적으로:

```text
COL <> 1
AND COL <> 2
AND COL <> NULL
```

| 상황                            | 결과        |
| ----------------------------- | --------- |
| 목록의 비NULL 값과 일치함              | `FALSE`   |
| 비NULL 값과 일치하지 않고 목록에 NULL 없음  | `TRUE`    |
| 비NULL 값과 일치하지 않지만 목록에 NULL 있음 | `UNKNOWN` |

예시:

| 표현                   | 결과        |
| -------------------- | --------- |
| `1 NOT IN (1, NULL)` | `FALSE`   |
| `2 NOT IN (1, NULL)` | `UNKNOWN` |
| `2 NOT IN (1, 3)`    | `TRUE`    |

따라서 정확한 표현은 다음이다.

> `NOT IN` 목록에 `NULL`이 포함되면, 목록의 비NULL 값과 일치하지 않는 행도 `UNKNOWN`이 되어 WHERE를 통과하지 못할 수 있다.

기존 자료의 “결과 집합이 비어버릴 수 있다”는 결론은 맞지만, 모든 경우가 반드시 `UNKNOWN`인 것은 아니다.

# 산술과 함수

## 7. 산술 연산의 NULL 전파

| 표현                           | 결과     |
| ---------------------------- | ------ |
| `10 + NULL`                  | `NULL` |
| `10 - NULL`                  | `NULL` |
| `10 * NULL`                  | `NULL` |
| `10 / NULL`                  | `NULL` |
| `COL1 + COL2`에서 `COL2`가 NULL | `NULL` |

| 규칙      | 설명                                        |
| ------- | ----------------------------------------- |
| NULL 전파 | 산술 연산에 `NULL`이 하나라도 포함되면 결과도 일반적으로 `NULL` |
| 예외 처리   | `NVL`, `COALESCE`, `ISNULL` 등으로 먼저 대체 가능  |

기존 자료의 산술 연산과 집계 함수의 차이 설명은 정확하다.

---

## 8. NULL 처리 함수

| 함수                  | 주요 DBMS         |    인수 | 동작                        |
| ------------------- | --------------- | ----: | ------------------------- |
| `COALESCE(a, b, …)` | 표준 SQL          | 2개 이상 | 왼쪽부터 첫 번째 NULL이 아닌 값 반환   |
| `NVL(a, b)`         | Oracle          |    2개 | `a`가 NULL이면 `b` 반환        |
| `IFNULL(a, b)`      | MySQL·SQLite 계열 |    2개 | `a`가 NULL이면 `b` 반환        |
| `ISNULL(a, b)`      | SQL Server      |    2개 | `a`가 NULL이면 `b` 반환        |
| `NULLIF(a, b)`      | 표준 SQL          |    2개 | 두 값이 같으면 NULL, 다르면 `a` 반환 |

기존 함수표는 대체로 정확하다. 

---

## 9. NULL 함수별 차이

| 구분    | `NVL`·`IFNULL`·`ISNULL` | `COALESCE`           |
| ----- | ----------------------- | -------------------- |
| 인수 개수 | 2개 고정                   | 2개 이상                |
| 처리 방식 | 첫 번째 값이 NULL이면 두 번째 값   | 왼쪽부터 첫 번째 NULL이 아닌 값 |
| 표준 여부 | DBMS별 함수                | 표준 SQL               |
| 범용성   | 낮음                      | 높음                   |

기존 자료의 이 비교는 유지해도 된다. 

---

## 10. NULLIF

| 표현               | 결과             |
| ---------------- | -------------- |
| `NULLIF(10, 10)` | `NULL`         |
| `NULLIF(10, 20)` | `10`           |
| `NULLIF(분모, 0)`  | 분모가 0이면 `NULL` |

0으로 나누기 방지:

```sql
분자 / NULLIF(분모, 0)
```

| 분모 | 처리                      |
| -: | ----------------------- |
|  5 | `분자 / 5`                |
|  0 | `분자 / NULL` → 결과 `NULL` |

| 주의  | 내용                    |
| --- | --------------------- |
| 자료형 | 두 인수는 비교 가능한 자료형이어야 함 |
| 오해  | 0을 다른 숫자로 바꾸는 것이 아님   |
| 결과  | 오류 대신 `NULL` 반환       |

기존 자료의 `NULLIF` 설명은 정확하다.

# 집계

## 11. 집계 함수의 NULL 처리

| 함수                  | NULL 처리     | 결과 기준                          |
| ------------------- | ----------- | ------------------------------ |
| `COUNT(*)`          | NULL 여부와 무관 | 모든 행                           |
| `COUNT(열)`          | NULL 제외     | 해당 열이 NULL이 아닌 행               |
| `COUNT(DISTINCT 열)` | NULL 제외     | NULL이 아닌 고유값                   |
| `SUM(열)`            | NULL 제외     | NULL이 아닌 값의 합                  |
| `AVG(열)`            | NULL 제외     | NULL이 아닌 값의 합 ÷ NULL이 아닌 값의 개수 |
| `MAX(열)`            | NULL 제외     | NULL이 아닌 값 중 최댓값               |
| `MIN(열)`            | NULL 제외     | NULL이 아닌 값 중 최솟값               |

기존 자료의 `COUNT(*)`, `COUNT(열)`, `AVG` 설명은 정확하다.

---

## 12. COUNT(*)와 COUNT(열)

예시 데이터:

| ID | SCORE |
| -: | ----: |
|  1 |    10 |
|  2 |  NULL |
|  3 |    20 |

| 표현             | 결과 | 이유                |
| -------------- | -: | ----------------- |
| `COUNT(*)`     |  3 | 행 3개              |
| `COUNT(SCORE)` |  2 | SCORE가 NULL인 행 제외 |
| `SUM(SCORE)`   | 30 | 10 + 20           |
| `AVG(SCORE)`   | 15 | 30 ÷ 2            |

`COUNT(*)`는 NULL을 하나의 값으로 세는 것이 아니라, **열 값과 관계없이 행을 센다.**

---

## 13. AVG와 NULL

| 오해                   | 실제 규칙 |
| -------------------- | ----- |
| NULL을 0으로 바꿔 평균 계산   | 아님    |
| NULL도 분모 행 수에 포함     | 아님    |
| NULL을 합계와 개수 모두에서 제외 | 맞음    |

예시:

| 값              | `AVG(값)` 계산              |
| -------------- | ------------------------ |
| `10, 20, NULL` | `(10 + 20) ÷ 2 = 15`     |
| `10, 20, 0`    | `(10 + 20 + 0) ÷ 3 = 10` |

따라서 `NULL`과 `0`은 평균에서 완전히 다르게 작용한다.

---

## 14. 공집합과 집계

WHERE 결과가 0행인 경우:

| 표현          | 결과          |
| ----------- | ----------- |
| 일반 `SELECT` | 0행          |
| `COUNT(*)`  | 값 0을 가진 1행  |
| `COUNT(열)`  | 값 0을 가진 1행  |
| `SUM(열)`    | NULL을 가진 1행 |
| `AVG(열)`    | NULL을 가진 1행 |
| `MAX(열)`    | NULL을 가진 1행 |
| `MIN(열)`    | NULL을 가진 1행 |

# JOIN

## 15. OUTER JOIN과 NULL

| 조인                 | 불일치 행 처리                     |
| ------------------ | ---------------------------- |
| `INNER JOIN`       | 제거                           |
| `LEFT OUTER JOIN`  | 왼쪽 행 유지, 오른쪽 열을 NULL로 채움     |
| `RIGHT OUTER JOIN` | 오른쪽 행 유지, 왼쪽 열을 NULL로 채움     |
| `FULL OUTER JOIN`  | 양쪽 불일치 행 유지, 반대편 열을 NULL로 채움 |

기존 자료의 OUTER JOIN 규칙은 정확하다. 

---

## 16. OUTER JOIN 이후 COUNT

예시:

```text
A 테이블: 3행
B와 매칭되는 A 행: 2행
B와 매칭되지 않는 A 행: 1행
```

LEFT JOIN 후:

| 표현            | 결과 |
| ------------- | -: |
| `COUNT(*)`    |  3 |
| `COUNT(B.ID)` |  2 |

| 이유            | 설명                        |
| ------------- | ------------------------- |
| `COUNT(*)`    | 매칭되지 않은 행도 하나의 결과 행이므로 셈  |
| `COUNT(B.ID)` | 미매칭 행의 `B.ID`는 NULL이므로 제외 |

기존 자료의 “OUTER JOIN으로 생긴 NULL을 COUNT(*)와 COUNT(열)에 다르게 적용”한다는 함정은 중요하다. 

---

# GROUP BY와 DISTINCT

## 17. GROUP BY의 NULL

일반 비교에서는:

```text
NULL = NULL
→ UNKNOWN
```

그러나 `GROUP BY`에서는 여러 NULL이 하나의 그룹으로 묶인다.

예시 데이터:

| REGION |
| ------ |
| 서울     |
| NULL   |
| NULL   |

```sql
SELECT REGION, COUNT(*)
FROM T
GROUP BY REGION;
```

결과 개념:

| REGION | COUNT(*) |
| ------ | -------: |
| 서울     |        1 |
| NULL   |        2 |

---

## 18. DISTINCT의 NULL

| 데이터                | `SELECT DISTINCT COL` 결과 |
| ------------------ | ------------------------ |
| `1, 1, NULL, NULL` | `1, NULL`                |

`DISTINCT`에서는 여러 NULL이 하나의 중복 결과처럼 정리된다.

---

# 정렬

## 19. ORDER BY의 NULL 위치

| DBMS       | `ASC` 기본 | `DESC` 기본 |
| ---------- | -------- | --------- |
| Oracle     | NULL 마지막 | NULL 처음   |
| SQL Server | NULL 처음  | NULL 마지막  |

기존 자료의 ASC 비교는 정확하지만, DESC까지 같이 적는 편이 완결적이다.

Oracle에서는 다음처럼 명시할 수 있다.

| 표현            | 의미            |
| ------------- | ------------- |
| `NULLS FIRST` | NULL을 먼저 배치   |
| `NULLS LAST`  | NULL을 마지막에 배치 |

# 제약조건과 모델링

## 20. PK와 NULL

| 제약조건          |  NULL 허용 | 설명                      |
| ------------- | :------: | ----------------------- |
| `PRIMARY KEY` |    불가    | 각 행을 식별해야 하므로 값이 반드시 존재 |
| `NOT NULL`    |    불가    | 해당 열의 NULL 저장 금지        |
| `UNIQUE`      | DBMS별 차이 | Oracle에서는 NULL 허용       |
| `FOREIGN KEY` | 가능할 수 있음 | 선택적 관계라면 NULL 허용 가능     |

기존 자료의 PK와 개체 무결성 연결은 정확하다.

---

## 21. PK와 UNIQUE 비교

| 항목      | PRIMARY KEY | UNIQUE       |
| ------- | ----------- | ------------ |
| 목적      | 행 식별        | 중복 방지        |
| NULL    | 불가          | Oracle에서는 허용 |
| 테이블당 개수 | 하나          | 여러 개 가능      |
| 개체 무결성  | 직접 관련       | 직접적인 PK는 아님  |

> UNIQUE와 NULL의 세부 동작은 DBMS마다 다를 수 있다.

# Oracle과 SQL Server 차이

## 22. 주요 DBMS 차이

| 항목         | Oracle             | SQL Server  |
| ---------- | ------------------ | ----------- |
| NULL 대체 함수 | `NVL`              | `ISNULL`    |
| 표준 다중 대체   | `COALESCE`         | `COALESCE`  |
| 빈 문자열 `''` | NULL처럼 취급          | NULL과 구분    |
| ASC 정렬     | NULL 마지막           | NULL 처음     |
| DESC 정렬    | NULL 처음            | NULL 마지막    |
| NULL 위치 명시 | `NULLS FIRST/LAST` | 직접 지원 방식 다름 |

# 대표 함정

## 23. 오개념 교정표

| 오개념                               | 실제 규칙                               |
| --------------------------------- | ----------------------------------- |
| `SUM`에 NULL이 하나라도 있으면 전체가 NULL    | `SUM`은 NULL을 제외하고 계산                |
| `AVG`는 NULL을 0으로 계산               | NULL을 합계와 개수 모두에서 제외                |
| `COUNT(*)`는 NULL값 자체를 센다          | 열 값과 관계없이 행을 셈                      |
| `COL = NULL`이면 NULL 행을 찾음         | 결과는 `UNKNOWN`; `IS NULL` 사용         |
| `IN`은 NULL 영향을 전혀 받지 않음           | 일치값이 없고 NULL이 있으면 `UNKNOWN`         |
| `NOT IN`에 NULL이 있으면 모든 경우 UNKNOWN | 일치값이 있으면 `FALSE`, 미일치 행은 UNKNOWN 가능 |
| OUTER JOIN이면 기준 행이 항상 최종 결과에 남음   | 이후 WHERE 조건이 NULL 행을 제거할 수 있음       |
| NULL과 0은 같다                       | 완전히 다름                              |
| NULL과 빈 문자열은 항상 같다                | Oracle에서는 유사하게 처리하지만 다른 DBMS는 구분    |
| `NULLIF(분모, 0)`은 0을 다른 값으로 바꿈     | 0을 NULL로 바꾸어 결과를 NULL로 만듦           |

# 최종 압축표

## 24. 위치별 NULL 규칙

| 위치           | 핵심 규칙                        |
| ------------ | ---------------------------- |
| 비교           | 일반 비교 결과는 `UNKNOWN`          |
| NULL 검사      | `IS NULL`, `IS NOT NULL`     |
| WHERE        | `TRUE`만 통과                   |
| 산술           | NULL 전파                      |
| `COUNT(*)`   | 모든 행                         |
| `COUNT(열)`   | NULL 제외                      |
| 주요 집계        | NULL 제외                      |
| `AVG`        | 분자·분모 모두 NULL 제외             |
| `IN`         | 미일치 + NULL 존재 시 UNKNOWN      |
| `NOT IN`     | NULL 때문에 미일치 행이 통과하지 못할 수 있음 |
| OUTER JOIN   | 미일치 반대편 열을 NULL로 채움          |
| GROUP BY     | NULL을 하나의 그룹으로 묶음            |
| DISTINCT     | 여러 NULL을 하나로 처리              |
| ORDER BY     | DBMS별 위치 차이                  |
| PK           | NULL 불가                      |
| UNIQUE       | Oracle에서는 NULL 허용            |
| Oracle 빈 문자열 | NULL처럼 취급                    |
