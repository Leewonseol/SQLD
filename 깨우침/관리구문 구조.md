# SQL 명령어 및 트랜잭션 분기표

## 트랜잭션이란?

> **트랜잭션(Transaction)은 하나의 논리적 업무를 완성하기 위해 함께 처리되는 데이터 변경 작업의 묶음이다.**

예를 들어 계좌이체는 다음 두 변경으로 이루어진다.

1. A 계좌의 잔액을 차감한다.
2. B 계좌의 잔액을 증가시킨다.

두 작업 중 하나만 실행되면 안 된다. 따라서 두 `UPDATE`를 하나의 트랜잭션으로 묶고 다음과 같이 처리한다.

- 모든 작업이 정상적으로 끝남 → `COMMIT`
- 중간에 문제가 발생함 → `ROLLBACK`
- 트랜잭션 중간에 복구 지점을 설정함 → `SAVEPOINT`

> **트랜잭션은 명령어 종류가 아니라 작업 묶음이고, TCL은 그 작업 묶음을 통제하는 명령어다.**

## 전체 분기표

```text
[SQL 명령어와 트랜잭션 제어를 분류한다]

무엇을 하려는가?
│
├─ 1. 누가 데이터베이스 객체에 무엇을 할 수 있는지 통제한다
│  └─ DCL
│     ├─ GRANT  : 사용자 또는 역할에 권한 부여
│     ├─ REVOKE : 사용자 또는 역할로부터 권한 회수
│     └─ ROLE   : 여러 권한을 하나의 묶음으로 관리
│
├─ 2. 데이터베이스의 대상을 직접 조작한다
│  │
│  ├─ 구조·객체 또는 객체 단위 상태를 조작한다
│  │  └─ DDL
│  │     ├─ CREATE   : 객체 생성
│  │     ├─ ALTER    : 객체 정의 변경
│  │     ├─ DROP     : 객체 자체 삭제
│  │     ├─ RENAME   : 객체 이름 변경
│  │     └─ TRUNCATE : 구조를 유지하고 전체 행 초기화
│  │
│  └─ 테이블 안의 행 데이터를 조작한다
│     └─ DML
│        ├─ INSERT : 행 추가
│        ├─ UPDATE : 행 값 수정
│        ├─ DELETE : 행 삭제
│        └─ MERGE  : 조건에 따라 삽입 또는 수정
│
└─ 3. 이미 수행한 행 데이터 변경 묶음을 통제한다
   └─ TCL
      ├─ 변경사항을 확정한다
      │  └─ COMMIT
      ├─ 미확정 변경사항을 취소한다
      │  └─ ROLLBACK
      └─ 중간 복구 지점을 설정한다
         └─ SAVEPOINT
```

## 사용자 기준 작업 흐름

```text
사용자가 데이터베이스 작업을 하려 한다
│
├─ 해당 작업을 수행할 권한이 있는가?
│  │
│  ├─ 없다
│  │  └─ DCL
│  │     └─ GRANT 또는 ROLE을 통해 권한 부여
│  │
│  └─ 있다
│     └─ 허용된 SQL 작업 수행
│        ├─ 구조·객체 조작 → DDL
│        └─ 행 데이터 조작 → DML
│
└─ DML로 변경 작업이 발생했다
   └─ TCL
      ├─ 확정 → COMMIT
      ├─ 취소 → ROLLBACK
      └─ 중간 복구 지점 설정 → SAVEPOINT
```

> **사용자 관점에서는 권한 확인이 작업의 관문이다. 다만 SQL 명령어 분류는 실행 순서가 아니라 각 명령의 역할을 기준으로 한다.**

## 네 영역의 핵심 질문

| 분류 | 핵심 질문 | 대표 명령어·개념 |
|---|---|---|
| DCL | 누가 무엇을 할 수 있는가? | `GRANT`, `REVOKE`, `ROLE` |
| DDL | 어떤 구조·객체를 만들거나 바꾸는가? | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE` |
| DML | 어떤 행 데이터를 조회·추가·수정·삭제하는가? | `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE` |
| TCL | 행 데이터 변경 작업을 확정·취소하거나 복구 지점을 둘 것인가? | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

> `SELECT`는 교재에 따라 DML에 포함하거나 DQL로 따로 분류하기도 한다. 이 문서에서는 SQLD 강의 자료의 분류를 반영해 DML 표에 함께 표시한다.

---

## DCL과 TCL의 차이

```text
DCL
└─ 작업을 수행하기 전·중·후에
   사용자 또는 역할의 권한을 통제한다
   ├─ GRANT
   ├─ REVOKE
   └─ ROLE

TCL
└─ DML로 발생한 변경 작업 묶음을 통제한다
   ├─ COMMIT
   ├─ ROLLBACK
   └─ SAVEPOINT
```

- DCL: **행위 주체와 권한**의 문제
- TCL: **변경 작업과 확정·취소**의 문제

---

## 한 문장 분류법

> **누가 무엇을 할 수 있는지 정하면 DCL, 구조·객체를 바꾸면 DDL, 행 데이터를 다루면 DML, 행 데이터 변경 묶음을 확정·취소하거나 복구 지점을 설정하면 TCL이다.**
