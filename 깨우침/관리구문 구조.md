# SQL 명령어 및 트랜잭션 분기표

## 트랜잭션이란?

> **트랜잭션(Transaction)은 데이터베이스가 하나의 논리적 작업 단위로 처리하는 하나 이상의 SQL 문장 묶음이다.**

트랜잭션은 반드시 여러 문장으로만 구성되는 것은 아니다. 하나의 `UPDATE`도 하나의 트랜잭션이 될 수 있다. 다만 여러 변경이 모두 성공하거나 모두 취소되어야 하는 업무에서 특히 중요하다.

예를 들어 계좌이체는 다음 두 변경으로 이루어진다.

1. A 계좌의 잔액을 차감한다.
2. B 계좌의 잔액을 증가시킨다.

두 작업 중 하나만 반영되면 안 된다. 따라서 두 `UPDATE`를 하나의 트랜잭션으로 처리한다.

* 모든 변경을 확정함 → `COMMIT`
* 미확정 변경 전체를 취소함 → `ROLLBACK`
* 트랜잭션 중간에 복구 지점을 설정함 → `SAVEPOINT`
* 특정 복구 지점 이후의 변경만 취소함 → `ROLLBACK TO SAVEPOINT`

> **트랜잭션은 논리적 작업 단위이고, TCL은 진행 중인 트랜잭션을 통제하는 명령어다.**

---

## 전체 분기표

```text
무엇을 하려는가?
│
├─ 1. 사용자나 역할의 권한을 부여하거나 회수한다
│  └─ DCL
│     ├─ GRANT
│     │  └─ 사용자 또는 역할에 권한이나 역할을 부여
│     └─ REVOKE
│        └─ 사용자 또는 역할로부터 권한이나 역할을 회수
│
│     ROLE
│     └─ 여러 권한을 하나로 묶어 관리하는 권한 객체
│
├─ 2. 데이터베이스 구조나 객체를 정의한다
│  └─ DDL
│     ├─ CREATE
│     │  └─ 객체 생성
│     ├─ ALTER
│     │  └─ 객체 정의 변경
│     ├─ DROP
│     │  └─ 객체 자체 삭제
│     ├─ RENAME
│     │  └─ 객체 이름 변경
│     └─ TRUNCATE
│        └─ 테이블 구조를 유지하고 전체 행 제거
│
├─ 3. 테이블의 행을 조회하거나 변경한다
│  └─ DML
│     ├─ SELECT
│     │  └─ 행 조회
│     ├─ INSERT
│     │  └─ 행 추가
│     ├─ UPDATE
│     │  └─ 행 값 수정
│     ├─ DELETE
│     │  └─ 행 삭제
│     └─ MERGE
│        └─ 조건에 따라 행 삽입 또는 수정
│
└─ 4. 현재 트랜잭션을 통제한다
   └─ TCL
      ├─ COMMIT
      │  └─ 미확정 변경을 확정하고 트랜잭션 종료
      ├─ ROLLBACK
      │  └─ 미확정 변경 전체를 취소하고 트랜잭션 종료
      ├─ SAVEPOINT
      │  └─ 트랜잭션 중간에 복구 지점 설정
      └─ ROLLBACK TO SAVEPOINT
         └─ 해당 지점 이후 변경만 취소하고 트랜잭션 계속
```

> 이 문서에서는 SQLD에서 사용하는 DDL·DML·DCL·TCL 분류를 따른다. DBMS 공식 문서에서는 일부 명령어의 분류가 다를 수 있다.

## 사용자 기준 작업 흐름

```text
사용자가 데이터베이스 작업을 하려 한다
│
├─ 해당 작업을 수행할 권한이 있는가?
│  │
│  ├─ 없다
│  │  └─ 권한 부여 권한을 가진 사용자가 GRANT 실행
│  │     ├─ 필요한 권한을 직접 부여
│  │     └─ 필요한 권한이 묶인 ROLE을 부여
│  │
│  └─ 있다
│     └─ 허용된 SQL 작업 수행
│        ├─ 구조·객체 정의 → DDL
│        └─ 행 조회·변경 → DML
│
└─ INSERT·UPDATE·DELETE·MERGE 등으로
   미확정 변경이 발생했는가?
   │
   ├─ 아니다
   │  └─ 확정하거나 취소할 데이터 변경 없음
   │
   └─ 그렇다
      └─ TCL로 현재 트랜잭션 통제
         ├─ 변경 확정 → COMMIT
         ├─ 변경 전체 취소 → ROLLBACK
         ├─ 복구 지점 설정 → SAVEPOINT
         └─ 지점 이후 취소 → ROLLBACK TO SAVEPOINT
```

> **사용자 관점에서는 권한이 작업 수행의 전제다. 다만 SQL 명령어 분류는 실행 순서가 아니라 각 명령어가 다루는 대상을 기준으로 한다.**

---

## 네 영역의 핵심 질문

| 분류  | 핵심 질문                             | 대표 명령어·개념                                                  |
| --- | --------------------------------- | ---------------------------------------------------------- |
| DCL | 누가 어떤 작업을 수행할 수 있는가?              | `GRANT`, `REVOKE` / 관련 개념: `ROLE`                          |
| DDL | 어떤 구조나 객체를 만들고 변경하거나 삭제하는가?       | `CREATE`, `ALTER`, `DROP`, `RENAME`, `TRUNCATE`            |
| DML | 어떤 행을 조회·추가·수정·삭제하는가?             | `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE`            |
| TCL | 현재 트랜잭션을 확정·취소하거나 복구 지점을 관리할 것인가? | `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `ROLLBACK TO SAVEPOINT` |

> `SELECT`는 교재에 따라 DML에 포함하거나 DQL로 따로 분류한다. 이 문서에서는 SQLD 강의 자료의 분류에 따라 DML에 포함한다.

## DCL과 TCL의 차이

```text
DCL
└─ 사용자나 역할의 권한을 통제한다
   ├─ GRANT
   │  └─ 권한 또는 역할 부여
   └─ REVOKE
      └─ 권한 또는 역할 회수

ROLE
└─ 여러 권한을 묶어 관리하는 권한 객체


TCL
└─ 현재 진행 중인 트랜잭션을 통제한다
   ├─ COMMIT
   │  └─ 변경 확정
   ├─ ROLLBACK
   │  └─ 변경 전체 취소
   ├─ SAVEPOINT
   │  └─ 복구 지점 설정
   └─ ROLLBACK TO SAVEPOINT
      └─ 특정 지점 이후 변경 취소
```

* DCL: **행위 주체와 권한**의 문제
* TCL: **변경 작업의 확정·취소·부분 복구** 문제

---

## 트랜잭션과 TCL의 관계

```text
INSERT·UPDATE·DELETE·MERGE 수행
              ↓
미확정 데이터 변경 발생
              ↓
하나의 논리적 업무 단위로 처리
              ↓
          트랜잭션
              ↓
        TCL로 결과 통제
       ├─ COMMIT
       ├─ ROLLBACK
       ├─ SAVEPOINT
       └─ ROLLBACK TO SAVEPOINT
```

트랜잭션은 작업 묶음 자체이고, `COMMIT`, `ROLLBACK`, `SAVEPOINT`는 그 묶음을 다루는 명령어다.

```text
트랜잭션
= 무엇을 하나의 작업 단위로 처리할 것인가

TCL
= 그 작업 단위를 어떻게 확정·취소·복구할 것인가
```

---

## SAVEPOINT와 ROLLBACK TO SAVEPOINT

```sql
SAVEPOINT sp1;
```

현재 트랜잭션의 중간 지점에 `sp1`이라는 복구 지점을 설정한다.

```sql
ROLLBACK TO sp1;
```

`sp1` 이후에 수행된 변경만 취소한다. 트랜잭션 전체는 종료되지 않으므로 이후 작업을 계속할 수 있다.

반면 다음 명령은 현재 트랜잭션의 미확정 변경 전체를 취소한다.

```sql
ROLLBACK;
```

```text
ROLLBACK
└─ 현재 트랜잭션의 미확정 변경 전체 취소

ROLLBACK TO SAVEPOINT
└─ 지정한 복구 지점 이후의 변경만 취소
```

## DML과 TCL의 관계에서 주의할 점

`SELECT`를 DML에 포함하더라도 일반적인 조회만으로 변경사항이 발생하는 것은 아니다. TCL이 직접 통제하는 핵심 대상은 다음과 같은 데이터 변경문이다.

```text
INSERT
UPDATE
DELETE
MERGE
```

따라서 다음 표현이 더 정확하다.

```text
DML을 실행했다
→ 반드시 TCL을 사용한다
```

가 아니라,

```text
INSERT·UPDATE·DELETE·MERGE 등으로
미확정 변경이 발생했다
→ 필요에 따라 TCL로 확정·취소·복구 지점 관리
```

이다.

DBMS나 클라이언트 설정에 따라 자동 커밋이 적용되거나 애플리케이션이 트랜잭션을 통제할 수도 있다.

---

## DDL과 트랜잭션의 관계

DDL은 데이터베이스 구조나 객체를 정의하는 명령어다.

```text
CREATE
ALTER
DROP
RENAME
TRUNCATE
```

Oracle에서는 DDL을 실행할 때 암시적 `COMMIT`이 발생하므로, 일반적인 DML처럼 실행 후 `ROLLBACK`으로 되돌릴 수 있다고 생각하면 안 된다.

```text
UPDATE 실행
→ COMMIT 전이라면 ROLLBACK 가능

CREATE·ALTER·DROP 등 DDL 실행
→ Oracle에서는 암시적 COMMIT 발생
→ 일반적인 ROLLBACK 대상이 아님
```

이 부분은 DBMS에 따라 트랜잭션 처리 방식이 다를 수 있다.

---

## 한 문장 분류법

> **누가 어떤 작업을 할 수 있는지 통제하면 DCL, 데이터베이스 구조나 객체를 정의하면 DDL, 테이블의 행을 조회하거나 변경하면 DML, 현재 트랜잭션을 확정·취소하거나 복구 지점을 관리하면 TCL이다.**

더 압축하면 다음과 같다.

```text
권한을 다룬다
→ DCL

구조와 객체를 다룬다
→ DDL

행 데이터를 다룬다
→ DML

미확정 변경 작업의 결과를 다룬다
→ TCL
```
