# JOIN·표준 JOIN 문제 풀이표

## 1. 전체 판독 순서

| 순서 | 확인할 질문                          | 판정 결과                                                 |
| -: | ------------------------------- | ----------------------------------------------------- |
|  1 | `FROM`에 테이블이 몇 개인가?             | 1개면 단일 테이블 조회, 2개 이상이면 JOIN 검토                        |
|  2 | 테이블 사이의 연결 조건이 있는가?             | 없으면 카티션 곱, 있으면 조건부 JOIN                               |
|  3 | 연결 조건이 `=`인가?                   | `=`이면 등가 조인, 범위·대소 비교면 비등가 조인                         |
|  4 | 일치하지 않는 행도 남기는가?                | `INNER`, `LEFT`, `RIGHT`, `FULL` 판정                   |
|  5 | 어떤 문법으로 조건을 작성했는가?              | `ON`, `USING`, `NATURAL JOIN`, 구문형 JOIN, Oracle `(+)` |
|  6 | JOIN 뒤에 추가 `WHERE` 조건이 있는가?     | OUTER JOIN으로 보존한 행이 다시 제거되는지 확인                       |
|  7 | 실제로 몇 개의 행 조합이 생기는가?            | 값별 매칭 횟수 계산                                           |
|  8 | `SELECT` 또는 `COUNT`가 무엇을 요구하는가? | 최종 출력값이나 행 수 계산                                       |

# JOIN

## 2. 테이블 수와 연결 조건

| 상황                  | 판정       | 결과              |
| ------------------- | -------- | --------------- |
| 테이블 1개              | JOIN 아님  | 해당 테이블만 조회      |
| 테이블 2개 이상, 연결 조건 없음 | 카티션 곱    | 모든 가능한 행 조합 생성  |
| 테이블 2개 이상, 연결 조건 있음 | 조건부 JOIN | 조건을 만족하는 행끼리 연결 |

### 카티션 곱 계산

| 계산 대상  | 규칙           |
| ------ | ------------ |
| 결과 행 수 | 각 테이블 행 수의 곱 |
| 결과 열 수 | 각 테이블 열 수의 합 |

예를 들어 A가 4행, B가 3행이면 결과는 `4 × 3 = 12행`이다. 첨부 JOIN 문제 6번도 카티션 곱의 행 수와 열 수를 구분해 묻는다. 

첨부 표준 JOIN 문제 9번에서는 A가 2행, B가 3행이므로 `CROSS JOIN` 결과는 6행이다. 

---

## 3. 등가 조인과 비등가 조인

| 구분       | 조인 조건                                  | 예시                                 |
| -------- | -------------------------------------- | ---------------------------------- |
| 등가 조인    | 두 열을 `=`로 비교                           | `A.ID = B.ID`                      |
| 비등가 조인   | `<`, `>`, `<=`, `>=`, `BETWEEN` 등으로 비교 | `A.SALARY BETWEEN B.MIN AND B.MAX` |
| 일반 필터 조건 | 한 테이블의 행을 추가로 제한                       | `A.SALARY > 3000`                  |

### 구분 예시

```sql
WHERE A.ID = B.ID
  AND A.SALARY > 3000
```

| 조건                | 역할                   |
| ----------------- | -------------------- |
| `A.ID = B.ID`     | 두 테이블의 행을 연결하는 조인 조건 |
| `A.SALARY > 3000` | 연결 결과에서 행을 거르는 일반 조건 |

첨부 JOIN 문제 1번의 `A.DEPTNO = B.DEPTNO`는 등가 조인이다. 

첨부 JOIN 문제 7번의 `A.SALARY BETWEEN B.MIN AND B.MAX`는 비등가 조인이다. 

---

## 4. 조인 결과 행 수 계산

| 단계 | 확인 내용                 |
| -: | --------------------- |
|  1 | A 테이블의 값을 하나 선택       |
|  2 | B 테이블에서 조건에 맞는 행 수 확인 |
|  3 | 일치하는 행 수만큼 결과 행 생성    |
|  4 | 모든 A 행에 대해 반복         |
|  5 | 생성된 결과 행 수 합산         |

### 중복값이 있는 등가 조인

특정 값 `x`의 결과 행 수는 다음과 같다.

```text
A에서 x의 빈도 × B에서 x의 빈도
```

첨부 JOIN 문제 5번:

| 테이블 | 값         |
| --- | --------- |
| T1  | `1, 2, 3` |
| T2  | `2, 2, 3` |

조인 조건:

```sql
T1.COL1 = T2.COL1
```

| T1 값 | T2에서 일치하는 행 수 | 결과 행 수 |
| ---: | ------------: | -----: |
|    1 |             0 |      0 |
|    2 |             2 |      2 |
|    3 |             1 |      1 |
|   합계 |               | **3행** |

따라서 답은 3행이다. 

---

## 5. 테이블 별칭

| 상황                  | 규칙                    |
| ------------------- | --------------------- |
| `FROM EMP A`        | `A`가 `EMP`의 별칭        |
| 별칭 선언 후 열 참조        | `A.ENAME` 사용          |
| 별칭 선언 후 원래 테이블명 사용  | 일반적으로 오류 또는 부적절       |
| 같은 열 이름이 여러 테이블에 존재 | 반드시 테이블명이나 별칭으로 소속 구분 |

예시:

```sql
FROM EMP A, DEPT B
```

| 올바른 참조    | 잘못된 참조       |
| --------- | ------------ |
| `A.ENAME` | `EMP.ENAME`  |
| `B.DNAME` | `DEPT.DNAME` |

첨부 JOIN 문제 2번은 별칭을 선언한 뒤 원래 테이블명을 사용한 오류를 묻는다.

# 표준 JOIN

## 6. 행 보존 방식

| 조인 종류              |  일치 행 | 왼쪽 불일치 행 | 오른쪽 불일치 행 |
| ------------------ | :---: | :------: | :-------: |
| `INNER JOIN`       |   유지  |    제거    |     제거    |
| `LEFT OUTER JOIN`  |   유지  |    유지    |     제거    |
| `RIGHT OUTER JOIN` |   유지  |    제거    |     유지    |
| `FULL OUTER JOIN`  |   유지  |    유지    |     유지    |
| `CROSS JOIN`       | 조건 없음 |   해당 없음  |   해당 없음   |

### 기억 규칙

| 문법      | 보존 대상  |
| ------- | ------ |
| `INNER` | 일치 행만  |
| `LEFT`  | 왼쪽 전체  |
| `RIGHT` | 오른쪽 전체 |
| `FULL`  | 양쪽 전체  |

첨부 표준 JOIN 문제 1번에서 INNER JOIN은 불일치 행을 `NULL`로 출력하지 않고 제외한다. 

---

## 7. INNER JOIN 예제

첨부 표준 JOIN 문제 2번:

| 학생 테이블 학번 | 성적 테이블 학번 |
| --------- | --------- |
| 202301    | 202301    |
| 202302    | 202302    |
| 202303    | 202304    |

공통값은 `202301`, `202302`이므로 결과는 2행이다. 

| 값      | 학생에 존재 | 성적에 존재 | INNER JOIN 결과 |
| ------ | :----: | :----: | :-----------: |
| 202301 |    O   |    O   |       유지      |
| 202302 |    O   |    O   |       유지      |
| 202303 |    O   |    X   |       제거      |
| 202304 |    X   |    O   |       제거      |

---

## 8. FULL OUTER JOIN 예제

첨부 표준 JOIN 문제 8번:

|  A |  B |
| -: | -: |
|  1 |  2 |
|  2 |  3 |

조인 조건:

```sql
A.ID = B.ID
```

|  값 | 위치     | FULL OUTER JOIN 결과 |
| -: | ------ | ------------------ |
|  1 | A에만 존재 | 유지                 |
|  2 | 양쪽에 존재 | 하나의 결합 행           |
|  3 | B에만 존재 | 유지                 |

결과는 총 3행이다. 

---

## 9. 표준 JOIN 문법

| 문법             | 사용 조건          | 특징                         | 주의점                      |
| -------------- | -------------- | -------------------------- | ------------------------ |
| `ON`           | 임의의 조인 조건      | 열 이름이 달라도 가능, 등가·비등가 모두 가능 | 가장 일반적                   |
| `USING`        | 양쪽 조인 열 이름이 같음 | 공통 열 이름을 한 번만 작성           | `USING(A.ID)`처럼 별칭 사용 불가 |
| `NATURAL JOIN` | 이름이 같은 공통 열 존재 | 같은 이름의 모든 열을 자동 사용         | 의도하지 않은 열까지 조건이 될 수 있음   |
| 구문형 JOIN       | `FROM A, B` 사용 | `WHERE`에 조인 조건 작성          | 조인 조건과 일반 조건이 섞이기 쉬움     |
| Oracle `(+)`   | 구문형 OUTER JOIN | 데이터가 부족한 쪽에 `(+)` 표시       | 추가 조건에서도 `(+)` 누락 주의     |
| `CROSS JOIN`   | 연결 조건 없음       | 모든 가능한 행 조합                | `ON` 사용하지 않음             |

---

## 10. ON

| 항목        | 내용           |
| --------- | ------------ |
| 조건 위치     | `ON` 뒤       |
| 열 이름      | 서로 달라도 가능    |
| 비교 방식     | 등가·비등가 모두 가능 |
| 일반 조건과 분리 | 가능           |
| 권장도       | 가장 높음        |

```sql
FROM A
JOIN B
  ON A.ID = B.MEMBER_ID
```

비등가 조건도 가능하다.

```sql
FROM EMP A
JOIN SALGRADE B
  ON A.SALARY BETWEEN B.MIN_SAL AND B.MAX_SAL
```

---

## 11. USING

| 판단 질문            | 답                |
| ---------------- | ---------------- |
| 양쪽 조인 열 이름이 같은가? | 같아야 사용 가능        |
| 비교 방식은?          | 등가 조인            |
| 열 이름은 몇 번 쓰는가?   | 한 번              |
| 별칭을 붙일 수 있는가?    | `USING` 내부에서는 불가 |

```sql
FROM A
JOIN B
USING (ID)
```

| 가능           | 불가능            |
| ------------ | -------------- |
| `USING (ID)` | `USING (A.ID)` |

첨부 표준 JOIN 문제 5번은 공통 컬럼명이 같고 등가 조인을 할 때 `USING`을 사용할 수 있는지를 묻는다. 

---

## 12. NATURAL JOIN

| 항목      | 내용                      |
| ------- | ----------------------- |
| 조인 열 지정 | 직접 하지 않음                |
| 자동 조건   | 이름이 같은 모든 열             |
| 조인 방식   | 기본적으로 동일 이름 열의 등가 조인    |
| 위험      | 공통 열이 추가되면 결과가 달라질 수 있음 |
| 실무 사용   | 드묾                      |

예시:

| A와 B의 공통 열 | 자동으로 생성되는 조건      |
| ---------- | ----------------- |
| `ID`       | `A.ID = B.ID`     |
| `NAME`     | `A.NAME = B.NAME` |

공통 열이 `ID`, `NAME` 두 개라면 둘 다 조건으로 사용된다.

첨부 표준 JOIN 문제 7번도 NATURAL JOIN의 공통 열 자동 사용과 별칭 제약을 묻는다. 

---

## 13. Oracle `(+)`

| 형태               | 의미                |
| ---------------- | ----------------- |
| `A.ID = B.ID(+)` | A 전체 보존, B가 부족한 쪽 |
| `A.ID(+) = B.ID` | B 전체 보존, A가 부족한 쪽 |

```text
(+)가 없는 쪽
→ 보존되는 기준 테이블

(+)가 있는 쪽
→ 데이터가 부족할 수 있는 테이블
```

### 주의사항

| 규칙                  | 설명                        |
| ------------------- | ------------------------- |
| 양쪽에 동시에 `(+)` 사용 불가 | 하나의 비교식에서 양쪽 외부 조인 지정 불가  |
| 관련 조건에 `(+)` 누락 주의  | 미일치 행이 `WHERE`에서 제거될 수 있음 |
| ANSI JOIN과 혼용 주의    | 한 문장 안에서 문법 혼용 지양         |

첨부 표준 JOIN 문제 3번은 `(+)`의 의미를 묻고, 문제 6번은 추가 조건에 `(+)`가 빠졌을 때 OUTER JOIN 효과가 사라질 수 있음을 묻는다. 

---

## 14. OUTER JOIN 이후 WHERE 조건

| 단계 | 처리                         |
| -: | -------------------------- |
|  1 | OUTER JOIN으로 기준 테이블 행 보존   |
|  2 | 짝이 없는 반대편 열에 `NULL` 생성     |
|  3 | `WHERE` 조건 평가              |
|  4 | `FALSE` 또는 `UNKNOWN`인 행 제거 |

예시:

```sql
FROM 회원 A
LEFT OUTER JOIN 연락처 B
  ON A.회원ID = B.회원ID
WHERE B.구분코드 = '휴대폰'
```

| 회원 상태      | JOIN 직후   | WHERE 평가 | 최종 결과 |
| ---------- | --------- | -------- | ----- |
| 휴대폰 연락처 있음 | B 값 존재    | TRUE     | 유지    |
| 다른 연락처만 있음 | B 값 존재    | FALSE    | 제거    |
| 연락처 없음     | B 열이 NULL | UNKNOWN  | 제거    |

따라서 LEFT JOIN을 했더라도 결과적으로 미일치 행이 사라질 수 있다.

첨부 표준 JOIN 문제 6번이 이 유형이다. 

---

## 15. LEFT JOIN과 `IS NULL`

```sql
SELECT COUNT(*)
FROM 회원 A
LEFT OUTER JOIN 회원연락처 B
  ON A.회원ID = B.회원ID
WHERE B.회원ID IS NULL;
```

| 단계 | 결과                           |
| -: | ---------------------------- |
|  1 | 회원 A 전체 보존                   |
|  2 | 연락처가 있으면 B와 결합               |
|  3 | 연락처가 없으면 B 열이 NULL           |
|  4 | `B.회원ID IS NULL`로 미연결 회원만 선택 |

최종 의미:

> 오른쪽 테이블에 대응 행이 없는 왼쪽 테이블의 행 수

즉 연락처가 없는 회원 수다. 첨부 표준 JOIN 문제 11번이 이 유형이다.

| 연결 조건         |                                          |

| 보존 테이블        |                                          |

| 추가 `WHERE` 조건 |                                          |

## 압축 암기표

| 질문                                   | 판정              |
| ------------------------------------ | --------------- |
| 조건이 없는가?                             | 카티션 곱           |
| `=`로 연결하는가?                          | 등가 조인           |
| 범위로 연결하는가?                           | 비등가 조인          |
| 일치 행만 필요한가?                          | INNER           |
| 왼쪽을 모두 살리는가?                         | LEFT            |
| 오른쪽을 모두 살리는가?                        | RIGHT           |
| 양쪽을 모두 살리는가?                         | FULL            |
| 공통 열 하나를 지정하는가?                      | USING           |
| 공통 열 전부를 자동 사용하는가?                   | NATURAL         |
| 조건을 직접 쓰는가?                          | ON              |
| OUTER JOIN 뒤 오른쪽 열을 `WHERE`에서 검사하는가? | NULL 행 제거 여부 확인 |
