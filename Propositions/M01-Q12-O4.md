# M01-Q12-O4 — VIEW는 SELECT문 기반 정의

## 문제 맥락

[[M01-Q12]]는 뷰(View)에 대한 설명으로 옳지 않은 것을 고르는 문제다.

## 기존 마인드맵 연결

- [[SQL 관리 구문#VIEW]] → SELECT 문을 저장해 가상 테이블처럼 사용하는 객체

## 이 선지가 시험하는 개념 관계

- [[VIEW]]는 SELECT 문을 기반으로 정의된다는 것이 원본 정의와 정확히 일치한다.

## Option Text

뷰는 SELECT문을 기반으로 정의된다.

## Contextual Proposition

뷰는 SELECT문을 기반으로 정의된다.

## Judgment

- 공식 정답 선지 여부: 아니오
- 문맥 명제의 참·거짓: 참

## 판별 과정

1. 뷰의 정의를 원본에서 확인한다.
2. "SELECT 문을 저장해 가상 테이블처럼 사용하는 객체"라는 서술과 이 선지가 일치함을 확인한다.
3. 틀린 내용이 없음을 확인한다.
4. 따라서 "옳지 않은 것"에 해당하지 않는다고 판단한다.

## 올바른 명제

뷰는 SELECT문을 기반으로 정의되는 가상 테이블이다(이 선지 자체가 이미 올바른 명제).

## 같은 문제의 다른 선지와 비교

- [[M01-Q12-O1]]: 다중 테이블 조합 가능은 옳은 설명으로 오답(정답 아님)이다.
- [[M01-Q12-O2]]: DML이 항상 가능하다는 주장은 복합 뷰 제약을 무시해 공식 정답이다.
- [[M01-Q12-O3]]: 데이터 미저장 설명도 옳아 오답이다.
- 이 선지는 O3과 함께 뷰의 정의·구조적 특징을 정확히 서술한다.
