# M01-Q47-O4 — TRUNCATE는 WHERE를 사용할 수 없음

## 문제 맥락

[[M01-Q47]]은 DROP, DELETE, TRUNCATE의 비교로 옳지 않은 것을 고르는 문제다.

## 기존 마인드맵 연결

- [[SQL 관리 구문#TRUNCATE]] → TRUNCATE는 WHERE 사용 불가(전체 삭제만 가능)

## 이 선지가 시험하는 개념 관계

- [[TRUNCATE]]는 WHERE절을 지원하지 않아 전체 삭제만 가능하므로, [[DELETE]] FROM 테이블 WHERE COL1='A'와 TRUNCATE TABLE 테이블 WHERE COL1='A'가 "동일한 결과"라는 이 선지는 애초에 TRUNCATE에 WHERE를 쓸 수 없다는 규칙과 모순된다.

## Option Text

DELETE FROM 테이블 WHERE COL1='A'와 TRUNCATE TABLE 테이블 WHERE COL1='A'는 동일한 결과를 출력한다.

## Contextual Proposition

DELETE FROM 테이블 WHERE COL1='A'와 TRUNCATE TABLE 테이블 WHERE COL1='A'는 동일한 결과를 출력한다.

## Judgment

- 공식 정답 선지 여부: 예(공식 정답 ④)
- 문맥 명제의 참·거짓: 거짓

## 판별 과정

1. TRUNCATE가 WHERE절을 지원하는지 원본에서 확인한다.
2. "WHERE 불가"로 명시되어 있어 TRUNCATE TABLE ... WHERE ... 자체가 문법 오류임을 확인한다.
3. DELETE는 WHERE로 특정 행만 삭제할 수 있지만 TRUNCATE는 전체 삭제만 가능해 애초에 비교 대상이 성립하지 않음을 비교한다.
4. 따라서 "동일한 결과"라는 이 선지는 옳지 않으며 공식 정답이라고 판단한다.

## 올바른 명제

TRUNCATE는 WHERE절을 사용할 수 없으며, DELETE WHERE와 같은 조건부 삭제를 수행할 수 없다.

## 같은 문제의 다른 선지와 비교

- [[M01-Q47-O1]]: DROP의 구조 영구 삭제 설명은 옳아 오답(정답 아님)이다.
- [[M01-Q47-O2]]: DELETE의 복구 가능 설명도 옳아 오답이다.
- [[M01-Q47-O3]]: DROP·TRUNCATE는 DDL, DELETE는 DML이라는 분류도 옳아 오답이다.
- 이 선지만 TRUNCATE에 존재하지 않는 문법(WHERE)을 전제로 한 오답이다.
