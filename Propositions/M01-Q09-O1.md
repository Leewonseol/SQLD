# M01-Q09-O1 — IE 표기법과 NOT NULL 표현

## 문제 맥락

[[M01-Q09]]는 IE·Barker 표기법에 대한 설명으로 올바르지 않은 것을 고르는 문제다.

## 기존 마인드맵 연결

- 원본에 IE·Barker 표기법 자체에 대한 서술이 없음(ERD 표기 규칙 공백)

## 이 선지가 시험하는 개념 관계

- [[ERD]]의 두 표기법 중 IE 표기법은 NOT NULL 여부를 확인할 수 없고, Barker 표기법만 NOT NULL 속성 앞에 별도 기호(*)를 붙여 표현할 수 있다는 점에서 "둘 다 가능하다"는 이 선지는 틀렸다.

## Option Text

IE 표기방식과 Barker 표기방식 모두 NOT NULL 여부를 확인할 수 있다.

## Contextual Proposition

IE 표기방식과 Barker 표기방식은 모두 NOT NULL 여부를 확인할 수 있다.

## Judgment

- 공식 정답 선지 여부: 예(공식 정답 ①)
- 문맥 명제의 참·거짓: 거짓

## 판별 과정

1. IE 표기법과 Barker 표기법 각각의 NOT NULL 표현 가능 여부를 확인한다(원본에는 규칙 자체가 없어 PDF 해설에 의존).
2. PDF 해설에 따르면 IE 표기법은 NULL 여부를 확인할 수 없다.
3. Barker 표기법만 NOT NULL 속성에 기호를 붙여 표현 가능함을 대조한다.
4. 따라서 "둘 다 가능하다"는 이 선지는 옳지 않은 설명이며 공식 정답이라고 판단한다.

## 올바른 명제

Barker 표기법만 NOT NULL 여부를 표현할 수 있으며, IE 표기법은 이를 확인할 수 없다.

## 같은 문제의 다른 선지와 비교

- [[M01-Q09-O2]]: 카디널리티는 두 표기법 모두 표현 가능하다는 옳은 설명으로 오답(정답 아님)이다.
- [[M01-Q09-O3]]: Barker의 #기호(식별자 표현)도 옳은 설명으로 오답이다.
- [[M01-Q09-O4]]: IE의 엔터티 내부 선 구분도 옳은 설명으로 오답이다.
- 이 선지만 "NOT NULL 확인 가능 여부"에서 IE와 Barker의 차이를 무시하고 동일하다고 잘못 서술한다.
