# M01-Q32-O4 — ==NULL은 SQL 문법이 아님

## 문제 맥락

[[M01-Q32]]는 SQL에서 NULL 비교가 옳은 방식을 고르는 문제다.

## 기존 마인드맵 연결

- [[SQL 기본#6. WHERE 절]] → 비교 연산자(=, !=, <>, ^=, >, <, >=, <=), "==" 연산자는 목록에 없음

## 이 선지가 시험하는 개념 관계

- SQL 표준 비교 연산자에는 "=="가 존재하지 않으며, [[NULL]] 비교는 더더욱 이 연산자로 할 수 없다.

## Option Text

WHERE COL==NULL

## Contextual Proposition

WHERE COL==NULL은 NULL을 비교하는 옳은 방식이다.

## Judgment

- 공식 정답 선지 여부: 아니오
- 문맥 명제의 참·거짓: 거짓

## 판별 과정

1. SQL의 표준 비교 연산자 목록(=, !=, <>, ^=, >, <, >=, <=)을 원본에서 확인한다.
2. "==" 연산자가 이 목록에 없음을 확인한다.
3. 존재하지 않는 연산자이므로 NULL 비교에도 사용할 수 없음을 비교한다.
4. 따라서 이 선지는 옳지 않다고 판단한다.

## 올바른 명제

SQL에는 "==" 비교 연산자가 없으며, NULL 비교에는 IS NULL을 사용해야 한다.

## 같은 문제의 다른 선지와 비교

- [[M01-Q32-O1]]: = NULL은 존재하는 연산자를 잘못 사용한 오답이다.
- [[M01-Q32-O2]]: != NULL도 같은 성격의 오답이다.
- [[M01-Q32-O3]]: IS NULL이 올바른 비교 방식이며 공식 정답이다.
- 이 선지는 O1·O2와 달리 SQL에 존재하지도 않는 연산자를 사용한 오답이다.
