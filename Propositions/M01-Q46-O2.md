# M01-Q46-O2 — TRUNCATE는 ROLLBACK으로 복구 불가능

## 문제 맥락

[[M01-Q46]]은 TRUNCATE 명령의 특징으로 옳지 않은 것을 고르는 문제다.

## 기존 마인드맵 연결

- [[SQL 관리 구문#TRUNCATE]] → 일반적으로 ROLLBACK 불가

## 이 선지가 시험하는 개념 관계

- [[TRUNCATE]]는 [[DDL]] 계열로 실행 즉시 자동 COMMIT되어 [[ROLLBACK]]으로 복구할 수 없는데, 이 선지는 "복구 가능"이라고 반대로 서술한다.

## Option Text

ROLLBACK으로 복구가 가능하다.

## Contextual Proposition

TRUNCATE는 ROLLBACK으로 복구가 가능하다.

## Judgment

- 공식 정답 선지 여부: 예(공식 정답 ②)
- 문맥 명제의 참·거짓: 거짓

## 판별 과정

1. TRUNCATE가 DDL 계열임을 원본에서 확인한다.
2. DDL은 실행 즉시 자동 COMMIT되어 일반적으로 ROLLBACK이 불가능함을 확인한다.
3. 이 선지가 "복구 가능"이라고 반대로 서술했음을 비교한다.
4. 따라서 이 선지는 옳지 않으며 공식 정답이라고 판단한다.

## 올바른 명제

TRUNCATE는 DDL이므로 실행 즉시 자동 COMMIT되어 ROLLBACK으로 복구할 수 없다.

## 같은 문제의 다른 선지와 비교

- [[M01-Q46-O1]]: 모든 데이터 삭제는 옳은 설명으로 오답(정답 아님)이다.
- [[M01-Q46-O3]]: DELETE보다 빠르다는 설명도 옳아 오답이다.
- [[M01-Q46-O4]]: 테이블 구조 유지 설명도 옳아 오답이다.
- 이 선지만 TRUNCATE의 ROLLBACK 가능 여부를 반대로 서술해 유일하게 틀렸다.
