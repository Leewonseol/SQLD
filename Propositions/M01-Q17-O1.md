# M01-Q17-O1 — SELECT는 DCL이 아님

## 문제 맥락

[[M01-Q17]]은 SQL 명령어 중 DCL에 해당하는 것을 고르는 문제다.

## 기존 마인드맵 연결

- SQL 관리 구문.md에는 DML(INSERT/UPDATE/DELETE/MERGE)만 있고, SELECT를 명시적으로 분류한 서술은 없음

## 이 선지가 시험하는 개념 관계

- SELECT는 [[DCL]](권한 제어)이 아니라 데이터 조회 명령이며, 원본에서는 DML 계열(INSERT/UPDATE/DELETE)과 이웃하지만 SELECT 자체가 명시적으로 분류되어 있지는 않다.

## Option Text

SELECT

## Contextual Proposition

SELECT는 DCL에 해당한다.

## Judgment

- 공식 정답 선지 여부: 아니오
- 문맥 명제의 참·거짓: 거짓

## 판별 과정

1. SELECT가 데이터를 "조회"하는 명령임을 확인한다.
2. DCL은 권한을 제어하는 명령(GRANT/REVOKE)임을 원본 부재 상태에서 PDF 해설로 확인한다.
3. SELECT가 권한 제어와 무관함을 비교한다.
4. 따라서 SELECT는 DCL이 아니라고 판단한다.

## 올바른 명제

SELECT는 데이터 조회 명령이며 DCL(GRANT/REVOKE)에 해당하지 않는다.

## 같은 문제의 다른 선지와 비교

- [[M01-Q17-O2]]: COMMIT은 TCL에 해당해 이 선지와 다른 오답 범주다.
- [[M01-Q17-O3]]: GRANT가 실제 DCL이며 공식 정답이다.
- [[M01-Q17-O4]]: CREATE는 DDL에 해당해 이 선지와 다른 오답 범주다.
- 네 선지는 각각 DML(추정)·TCL·DCL·DDL을 대표해 SQL 명령어 4대 분류를 시험한다.
