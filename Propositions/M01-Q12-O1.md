# M01-Q12-O1 — VIEW의 다중 테이블 조합

## 문제 맥락

[[M01-Q12]]는 뷰(View)에 대한 설명으로 옳지 않은 것을 고르는 문제다.

## 기존 마인드맵 연결

- [[SQL 관리 구문#VIEW]] → SELECT 문을 저장해 가상 테이블처럼 사용

## 이 선지가 시험하는 개념 관계

- [[VIEW]]는 하나의 SELECT 문을 저장하므로, 그 SELECT가 여러 테이블을 JOIN한다면 뷰도 여러 테이블을 조합해 생성할 수 있다.

## Option Text

뷰는 하나 이상 테이블 조합하여 생성 가능하다.

## Contextual Proposition

뷰는 하나 이상의 테이블을 조합하여 생성할 수 있다.

## Judgment

- 공식 정답 선지 여부: 아니오
- 문맥 명제의 참·거짓: 참

## 판별 과정

1. VIEW가 SELECT 문을 저장하는 객체임을 확인한다.
2. SELECT 문 자체가 여러 테이블을 JOIN할 수 있음을 상기한다.
3. 따라서 뷰도 여러 테이블을 조합해 정의할 수 있음을 확인한다.
4. 이 서술이 틀리지 않았으므로 "옳지 않은 것"에 해당하지 않는다고 판단한다.

## 올바른 명제

뷰는 하나 이상의 테이블을 조합한 SELECT 문으로 생성할 수 있다(이 선지 자체가 이미 올바른 명제).

## 같은 문제의 다른 선지와 비교

- [[M01-Q12-O2]]: DML이 항상 가능하다는 주장은 복합 뷰의 제약을 무시해 공식 정답이다.
- [[M01-Q12-O3]]: 데이터를 저장하지 않는다는 설명도 옳아 오답(정답 아님)이다.
- [[M01-Q12-O4]]: SELECT문 기반 정의도 옳아 오답이다.
- 이 선지는 O3·O4와 함께 뷰의 정상적인 특징을 서술한다.
