# 13. kNN 결측값 대체

## 1. 학습 목표

- 유클리드 거리 기반 kNN(k-최근접이웃) 대체를 SQL(Oracle/SQL Server)로 직접
  구현한다.
- `12-평균-중앙값대치`의 평균/중앙값 대체와 RMSE를 나란히 비교해, 언제
  kNN이 낫고 언제 아닌지를 데이터로 확인한다.
- 결측 대치가 SQL의 윈도우 함수(`ROW_NUMBER`, `RANK`)·집계·조인을 실전
  문제에서 어떻게 조합해 쓰는지 종합적으로 익힌다.

## 2. 핵심 원리

- kNN 대체는 "결측값이 있는 행과 가장 비슷한(거리가 가까운) k개의 완전한
  행을 찾아, 그 이웃들의 평균으로 결측을 채운다"는 아이디어다.
- 거리는 유클리드 거리 `d = sqrt(Σ(x_i - y_i)^2)`를 쓰되, 비교 대상 행 자체에
  NULL이 섞여 있으면(예: `C017`의 `recency`, `delivery_days`) 그 변수는
  거리 계산에서 제외하고, 사용된 변수 개수로 정규화한다(
  `sqrt(제곱합 / 사용된 변수 개수)`).
- 이웃 수 `k`는 `round(sqrt(도너 풀 크기))`(Jonsson & Wohlin, 2004) 규칙을
  쓴다 — 도너 풀 15행이므로 `k = round(sqrt(15)) = 4`.
- **이 폴더는 `분석기법/22-KNN결측값대체`가 이미 구현한 10단계 파이프라인
  중 결측 대치에 직접 필요한 STEP 5~10만 축약해 재현한 것이다.** 거리
  정규화·동률 처리 등 설계 배경의 상세 논증은 그 모듈의 README를 참고하고
  여기서는 반복하지 않는다.

## 7. 결과 차이의 이유

계산 결과(거리·k·대체값)는 Oracle과 SQL Server가 완전히 같다 — 순수 산술과
표준 윈도우 함수라 DBMS별 차이가 없다. 차이는 `GO` 배치 구분자, `MEDIAN()`
대 `PERCENTILE_CONT()` 같은 문법뿐이다.

## 8. SQLD 함정

- **동률(tie) 이웃 처리 방식에 따라 결과가 달라짐** — `ROW_NUMBER`(정확히
  k명만)와 `RANK`(동률 전부 포함)는 서로 다른 대체값을 낸다. "k=4"라는
  숫자만으로는 결과가 유일하게 정해지지 않는다는 것을 보여준다.
- **"kNN이 항상 평균/중앙값 대체보다 낫다"는 일반화** — `C019`(진짜 가까운
  이웃이 사실상 1개뿐인 특이 관측치)에서는 고정 k=4가 오히려 관계없는
  이웃들을 강제로 섞어 오차를 키운다(`분석기법/22-KNN결측값대체/README.md`
  "실행 결과" 절 참고). 전체 RMSE만 보고 kNN이 이겼다고 결론 내리면, 이런
  개별 사례의 실패를 놓친다.
- **거리 계산에 쓰인 변수 개수가 행마다 다를 수 있다는 것을 놓치는 함정** —
  `C017`처럼 NULL이 여러 개인 행은 정규화하지 않으면 인위적으로 더
  "가까워" 보일 수 있다.

## 9. 빅분기 결측치 처리와의 연결

`sklearn.impute.KNNImputer`가 내부적으로 하는 계산(거리 계산 → k개 이웃
선택 → 평균으로 대체)을 SQL로 직접 구현한 것이 이 폴더다. 빅분기 실기에서
"왜 KNNImputer를 썼는가"를 설명할 때, 이 SQL 파이프라인의 각 STEP이 곧
그 설명의 근거가 된다 — 특히 STEP 7의 RMSE 비교는 "다른 대치 방법과
비교했을 때 이 방법이 더 낫다는 근거"를 요구하는 실기 서술형 문제에
그대로 쓸 수 있는 형식이다.

## 12. 실제 실행 검증 여부

**Oracle·SQL Server 모두 미검증** — 이 세션에는 두 DBMS 실행 환경이 없다.
다만 이 폴더가 재사용하는 로직(거리 계산, k=4, strict/with_ties 대체,
RMSE)은 `분석기법/22-KNN결측값대체/optional/01_prepare_sqlite.sql` +
`03_verify_sqlite.sql`로 **이 저장소에서 실제 실행·검증됐다**(SQLite,
Python `02_analyze.py`의 numpy 재구현과도 오차 없이 일치 확인됨). Oracle/
SQL Server 문법 자체의 실제 동작은 각 환경에서 재확인이 필요하다.
