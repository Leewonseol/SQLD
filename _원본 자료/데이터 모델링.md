# 데이터 모델링

## 1. 정의

- 현실의 대상을 데이터로 저장·활용하기 위한 설계 과정
- 어디에 어떤 데이터를 저장할지 결정
- 복잡한 현실 세계를 단순화·추상화·명확화

## 2. 특징

- **단순화**: 약속된 표기법으로 복잡한 현실을 간단히 표현
- **추상화**: 구체적인 대상에서 공통된 특징만 추출
- **명확화**: 누구나 같은 의미로 이해할 수 있도록 표현

## 3. 관점

- **데이터 관점(What)**: 업무가 어떤 데이터와 관련되는가
- **프로세스 관점(How)**: 업무가 어떤 흐름과 절차로 수행되는가
- **상관 관점(CRUD)**: 업무 흐름에 따라 데이터가 생성·조회·수정·삭제되는가를 CRUD로 표현

## 4. 중요성

- **파급효과 감소**: 설계 없이 개발하면 요구사항 변경 시 구조 전체 수정 위험
- **요구사항의 간결한 표현**: 그림으로 표현해 관계자 간 공통 이해 가능
- **데이터 품질 확보**: 중복/비유연성/비일관성 방지

## 5. 데이터 품질 저하의 3요소

- **중복**
    - 동일 데이터를 여러 장소에 반복 저장
    - 수정 시 일부만 변경되면 신뢰성 저하
- **비유연성**
    - 데이터와 업무 프로세스가 지나치게 긴밀하게 결합
    - 작은 업무 변화에도 구조 변경이 필요
- **비일관성**
    - 동일한 상황이 서로 다른 방식으로 처리
    - 같은 데이터가 서로 다른 값으로 저장될 수 있음

## 6. 데이터 모델링 3단계

- **개념적 데이터 모델링**
    - 현업 요구사항을 바탕으로 필요한 데이터를 결정
    - 가장 높은 추상화 수준, 업무 중심
    - 엔터티와 관계 표현
    - ERD 작성
    - EA 수준에서도 활용 가능
    - DBMS에 독립적
- **논리적 데이터 모델링**
    - 개념 모델을 상세한 데이터 구조로 구체화
    - 속성 입력
    - 식별자 설정
    - 관계 설정
    - 정규화 수행
    - 제약조건 반영
    - 모든 요구사항을 반영해야 함
    - 실제 개발·운영에 재사용 가능
- **물리적 데이터 모델링**
    - 논리 모델을 실제 DBMS에 구현 가능하게 변환
    - 테이블·컬럼 생성
    - 자료형·길이 결정
    - 저장 방식 결정
    - 인덱스·파티셔닝 등 성능 고려
    - SQL로 구현
    - 가장 구체적인 단계
- **단계별 목적**
    - 개념적 → 비즈니스 이해
    - 논리적 → 정확한 설계
    - 물리적 → 실제 구현

## 7. 데이터베이스의 독립성

- **정의**: 한 계층의 구조가 변경돼도 다른 계층에 영향을 최소화
- **외부 스키마**: 사용자 관점(사용자별 필요한 데이터만 표현), 여러 개 존재 가능
- **개념 스키마**: 통합 관점(전체 데이터베이스의 논리적 구조), 하나만 존재
- **내부 스키마**: 물리적 관점(데이터의 실제 저장 구조)
- **논리적 독립성**: 개념 스키마 변경 시 외부 스키마 영향 최소화
- **물리적 독립성**: 내부 저장 구조 변경 시 개념·외부 스키마 영향 최소화

## 8. 데이터 모델의 이해관계자

- 개발자: 데이터 모델을 이해하고 시스템 구현
- DBA: 백업·복구·권한·SQL 튜닝 등 DB 전반 관리
- 현업 담당자: 요구사항 반영 검토, 업무 관점 의견 제시
- 전문 모델러: 대형 프로젝트에서 데이터 모델링을 전문적으로 수행

## 9. 구성요소

### 엔터티(Entity)

- **정의**: 업무에 필요한 정보를 저장·관리하기 위한 집합적·포괄적 대상
- **인스턴스(Instance)**: 엔터티에 속하는 개별 데이터(엔터티는 인스턴스의 집합)
- **특징**: 업무에 필요한 정보 / 2개 이상의 인스턴스 / 1개 이상의 속성 / 다른 엔터티와 관계 / 식별자 존재
- **유형 분류**: 유형 / 개념 / 사건
- **발생 시점 분류**: 기본(키) / 메인(중심) / 행위
- **명명 규칙**: 현업 용어, 약어 지양, 단수형, 모델 내 유일, 생성 의도에 맞게

### 속성(Attribute)

- **정의**: 엔터티가 가지는 업무상 관리 대상인 구체적 정보 항목
- **특징**: 업무상 필요한 데이터 / 최소 단위 / 주식별자에 함수적으로 종속 / 하나의 속성에 하나의 값
- **분류**: 기본 / 설계 / 파생
- **구성 방식**: PK / FK / 일반 속성
- **도메인**: 데이터 타입, 허용 범위, 형식, 제약조건의 집합
- **명명 규칙**: 약어 자제, 명사형·복합명사, 모델 내 유일

### 관계

- **정의**: 둘 이상의 엔터티 사이에 존재하는 의미 있는 논리적 연결
- **분류**: 존재적 관계 / 행위적 관계
- **표현 3요소**: 관계명 / 관계차수 / 관계선택성
- **M:N 관계**: 관계 엔터티를 추가해 1:M과 M:1로 해소

### 식별자

- **정의**: 엔터티 인스턴스를 유일하게 식별하는 속성 또는 속성 집합
- **분류**: 주/보조, 내부/외부, 단일/복합, 본질/인조
- **주식별자 특징**: 유일성/최소성/불변성/존재성(NULL 불가)
- **식별 관계 vs 비식별 관계**
    - 식별: 부모 없이 자식 생성 불가, 생명주기 결합, 무결성에 유리
    - 비식별: 자식 독립 생성 가능, 단순한 식별자에 유리

## 10. 정규화

- **정의**: 데이터 이상 현상 방지를 위해 엔터티를 분리(중복 제거, 데이터 품질 향상)
- **이상 현상**: 삽입 이상 / 갱신 이상 / 삭제 이상
- **함수적 종속**: X → Y
- **정규화 단계**: 1NF → 2NF → 3NF → BCNF → 4NF → 5NF
- **실무 중요 범위**: 보통 3NF까지
- **반정규화**: 조회 성능 향상을 위해 통합·중복 허용(무결성/품질 저하 가능)
- **핵심**: 정규화가 조회 성능을 항상 보장하진 않으며, 반정규화는 조회 성능을 올릴 수 있지만 조작 성능·품질을 희생할 수 있음
